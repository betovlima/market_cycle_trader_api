# MCT API v10.8.53 — One-shot Meta-Veto + Strict Causal Maturity

## Why this version exists

The v10.8.52 replay restored exact v10.8.44 Liquidity-Aware parity, but its
Meta-Veto path collapsed because a decision intended to mean "HOLD once, then
Control" could be vetoed again on the very next policy call. This created
recursive lock-in, including a 333-decision veto streak in Fold 2.

A second audit found that Fold 3 training used 191 prior rollout labels although
only 184 had fully matured before Fold 3 started. Seven late Fold 2 rollouts
ended inside Fold 3.

v10.8.53 fixes both implementation errors without changing the model hypothesis.

## Frozen model contract

Unchanged from v10.8.51/v10.8.52:

- balanced L2 Logistic Regression;
- C = 0.25;
- the same 9 v10.8.50 features;
- chronological 70/30 train/calibration;
- minimum calibration rows = 20;
- calibration Balanced Accuracy >= 0.52;
- calibration ROC AUC >= 0.52;
- veto only when P(ROTATE better) <= 0.35;
- CASH transitions never modified.

## One-shot veto semantics

If a rotation is vetoed at decision t:

1. t executes HOLD of the incumbent;
2. the next policy call t+1 is forced to execute the Control decision;
3. only after that call may the Meta-Veto evaluate another opportunity.

This exactly matches the v10.8.48 training target:

HOLD once -> then same Control policy.

No cooldown length or threshold was tuned from the failed capital result.

## Strict maturity

Training eligibility additionally requires:

`rollout_end_date < test_start`

The maturity date comes from the frozen v10.8.48
`paired_rollout_labels.csv`.

Expected historical eligibility:

- Fold 1: no model;
- Fold 2: 75 fully matured Fold 1 labels;
- Fold 3: 184 fully matured prior labels, not 191.

The seven excluded Fold 2 labels mature after Fold 3 begins.
