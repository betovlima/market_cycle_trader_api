## Root-cause hypothesis to test

The same LightGBM hyperparameters and runtime receive numerically near-
identical but not bitwise-identical matrices. Determine whether CLMT model
differences arise in the training **features**, **target labels**, or at
prediction time from slightly different inference features. Do not assume
the CSV-vs-BSON parsing mechanism or automatically exclude an asset.

## Scope of the new script

`scripts/audit_tcc_v106_clmt_input_isolation.py`:

1. validates the original 112 frozen TCC files and current MCT per-asset RAW
   plus normalized fingerprints against Strategy #11 archive;
2. checks exactly aligned CLMT train and calibration dates;
3. exports each numeric training feature/target's count of exact differences,
   maximal absolute delta, first affected date and both values' `float.hex()`;
4. fits CLMT ONLY using five controlled variants:
   original TCC, original MCT, TCC feature/MCT target, MCT feature/TCC
   target, and TCC target/MCT features on the TCC source frame;
5. cross-predicts each fitted model on the original TCC and MCT CLMT
   inference frames; records model fingerprints and first changed tree;
6. checks the original CLMT predictions against the previous calibration
   audit before reporting results.

It does not retrain all 55 models or rerun the three folds. No changes to
model settings, Strategy #11/#12, the original TCC or database. The output
is diagnostic, not permission to alter or repair historical CLMT prices.

## Final outcome — completed local output(20260925-224028).zip

The user ran the v10.8.32 audit to completion. Scope remains *the frozen
TCC-main snapshot used in the comparison* against archived MCT Strategy #11,
not an assertion about untracked data at the earlier TCC v1.0.6 source tag.

Results: 700 training rows; 126 calibration dates; 44 feature columns with
bitwise differences, 200 differing target values, **zero** feature/target
differences exceeding 1e-12. Replayed original CLMT predictions match
the prior Fold-1 audit to a maximum absolute error of ~9.7e-17.

Controlled five-fit crossover:

| CLMT training variant | Model fingerprint versus TCC | Changed calibration predictions |
|---|---|---:|
| TCC original | Identical | 0/126 |
| MCT original | Different | 126/126 |
| TCC features + MCT target | Identical | 0/126 |
| MCT features + TCC target | Different, identical to MCT original | 126/126 |
| MCT features + TCC target (on TCC base frame) | Different, identical to MCT original | 126/126 |

The third feature/target hybrid stored as
`tcc_target_mct_features` is the same MCT-features/TCC-target input built
on the TCC base frame. Its model fingerprint also equals the MCT original.
Switching only target values never changes the learned model, whereas
switching the (sub-1e-12) training feature representation is sufficient.
Cross-inference of each fitted model on either original TCC or MCT
calibration panel produces identical predictions for that model. Thus
**the difference originates during CLMT model training from feature
precision, not target precision or differences in inference features**.

MCT vs TCC CLMT predictions differ for all 126 calibration dates, max
absolute delta `0.035054832000237006`. Tree index 0 is already different
although the recorded root split feature index and root threshold agree;
the report doesn't identify the exact deeper tree element. The downstream
v10.8.31 score-column crossover separately proved that exchanging CLMT
predictions alone reverses Fold-1 candidate-margin selection in both
directions.
