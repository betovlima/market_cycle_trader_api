## Code correction

The MCT reference adapter now requires the resolved
`analysis_end_date` explicitly when constructing the two execution
configs. Both versions are copied from the vendored original with the
*same* job cutoff; the frozen `TCC_V106_CONFIG` itself is never mutated.
An empty cutoff raises rather than silently falling back to the old
scientific constant. Per-result metadata and the comparison export
include `requested_analysis_cutoff` and `effective_analysis_cutoff`.

The independent TCC repository and frozen CSV snapshot remain unchanged.
The MCT route for `tcc_frozen_main` still explicitly queues the **scientific
cutoff 2026-09-17**. Normal `mct_current` queues the latest safely closed
XNYS session and performs the complete RAW/SIP refresh. Data-source
selection is already frozen in the immutable request (v10.8.34).

The backtest's **last execution timestamp** may be one session earlier
than the raw bar cutoff depending on the engine's next-open decision
timeline. Check the job's requested/effective cutoff, refreshed data
signature and result timestamp together; do not conflate these fields.
