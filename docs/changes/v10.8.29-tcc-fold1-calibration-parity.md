## Scope of this version

New `scripts/audit_tcc_v106_fold1_calibration_parity.py`:
1. verifies both original MCT archives, the completed v10.8.28 audit,
   and the 112 individual official TCC files against the frozen manifest;
2. checks the *current* MCT RAW and normalized cache per-symbol against the
   archived #11 hashes; aborts on any drift (no Alpaca refresh);
3. loads frozen TCC and archived MCT inputs separately using the **same
   vendored TCC v1.0.6 preparation code** and compares Fold-1
   chronological train/calibration dates, ordered assets and training
   matrices;
4. in the same CPU/Python/LightGBM runtime, fits only Fold-1 calibration
   models on each dataset with exactly the same LightGBM settings;
5. exports per-candidate economic calibration scores, selected margin,
   model fingerprints and session-by-asset calibration predictions; compares
   the MCT replay scores against original Strategy #11 archived candidates.

It does not run folds 2/3, final-fit models or an OOS portfolio simulation.
No writes to MongoDB, source TCC files, Strategy profiles, live Trader,
or vendored engine. No changes to scientific policy/parameters.

## Interpretation of paired experiment

- Same chronological training matrices to tolerance but different selected
  margin: inspect exact float discrepancies, tree fingerprints and model
  prediction vectors. If the MCT replay matches archive #11, this directly
  isolates the source-dataset sensitivity on one runtime.
- Same selected margin and candidate scores on BOTH datasets but they
  differ from archived #11: investigate runtime, dependency versions,
  threading, and/or the MCT #11 engine calibration implementation.
- Different selected margin on each dataset but different MCT replay from
  archive: cannot isolate data as causal; environment/engine divergence
  must first be resolved.

This is a diagnostic, not a parameter search; never set margin manually to
produce a desired ending capital.

## CI correction — same v10.8.29 branch

The initial CI run 36168377131 completed with two new test errors,
`test_exact_match` and `test_small_float_drift`.
Cause: NumPy index arrays `bad` and `unequal` were used directly as
boolean conditions in the diagnostic-only `_status_pair`. Under the
current NumPy runtime the truth value of an empty array is ambiguous.
Use `bad.size` and `unequal.size` explicitly. This changes no model,
market data, or backtest result. Re-run the existing regression suite
on the new HEAD before executing the local paired calibration.
