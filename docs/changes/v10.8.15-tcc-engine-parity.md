# API v10.8.15 — TCC backtest engine parity

## Context

The standalone TCC project `tcc_mba_usp_data_science_analytics` evolved the
single-position LightGBM backtest engine after it was extracted from Market
Cycle Trader. Several changes are engine improvements rather than TCC-specific
infrastructure.

This release ports those reusable improvements back into the MCT API while
preserving the production API contracts and all advanced MCT research modes.

Source used for comparison:

- TCC branch: `fix/v1.2.0-inclusive-analysis-end`;
- TCC version: `1.2.0-dev.9`;
- MCT base: `main`, API `10.8.14`;
- MCT delivery branch: `feature/v10.8.15-tcc-engine-parity`.

## Improvements ported

### Data-driven market calendar

The backtest no longer depends on manually configured calendar anchors to
construct the execution calendar.

The engine now selects the valid asset with the longest prepared history.
Ties are resolved deterministically by:

1. earliest valid start;
2. latest valid end;
3. symbol.

The public `prepare_rotation_panel` signature remains compatible. The selected
calendar source is also exposed in result metrics as
`calendar_source_asset`.

The legacy `calendar_anchor_assets` request field is retained for API/database
compatibility but no longer controls the backtest calendar.

### Inclusive analysis end date

`analysis_end_date` is interpreted as an inclusive market date.

Daily NYSE bars may be represented at 04:00 or 05:00 UTC. Comparing those
timestamps with midnight UTC could exclude the requested final market session.

The engine now uses the beginning of the following UTC day as an exclusive
search boundary. This preserves the requested final market date and excludes
the following date.

### CAGR from the true initial capital

Strategy and benchmark CAGR calculations now use the configured initial capital
instead of implicitly assuming the first OOS equity observation is the initial
capital.

This aligns the API result with the actual compounded-capital experiment.

### Per-horizon target columns

The prepared rotation frame now persists, in memory, the individual target for
every configured horizon:

- `forward_horizon_utility_<horizon>`;
- `forward_horizon_net_log_return_<horizon>`.

The original weighted targets remain unchanged.

These columns make the individual horizons available to the optional Soft
Horizon Consensus policy without changing the Control target.

### Batched LightGBM OOS inference cache

For the single-position LightGBM policy, model predictions for each fold can be
computed in batches and cached by decision date.

The cached values are consumed by the same policy functions used by row-wise
inference. The engine records:

- cache build time;
- number of sessions;
- number of symbols;
- model predict calls;
- number of predicted rows.

The optimization is not forced on allocation/risk-overlay execution paths,
which retain their existing behavior.

### LightGBM predictive diagnostics

Each calibration model now records descriptive predictive diagnostics without
using them as a business/promotion gate:

- training MAE;
- training RMSE;
- chronological calibration MAE;
- chronological calibration RMSE;
- RMSE generalization gap;
- gain-based feature importance;
- top features by gain.

Early stopping remains disabled for this economic ranking model, matching the
validated TCC behavior.

### Optional Soft Horizon Consensus

The API can enable the TCC Soft Horizon Consensus through
`research_model_settings`:

```json
{
  "soft_horizon_consensus": {
    "enabled": true,
    "penalty_strength": 1.0
  }
}
```

When enabled, the engine:

1. keeps the original weighted-utility LightGBM policy as the base policy;
2. trains one additional LightGBM utility model per configured horizon;
3. converts each horizon into a deterministic asset ranking;
4. combines rankings with the configured horizon weights;
5. increases the switch margin when multi-horizon support for a marginal
   rotation is weak;
6. preserves CASH decisions and ordinary HOLD decisions from the base policy.

The feature is opt-in and disabled by default.

To prevent ambiguous combinations, Soft Horizon Consensus is currently
supported only by the base single-position LightGBM rotation mode. Risk-Off,
Selective Opportunity, Cash Gate, Optimized Allocation, Concentrated
Allocation and Compound Risk Overlay continue to use their existing execution
logic.

## MCT behavior deliberately preserved

The following MCT capabilities were not removed or replaced:

- Explicit Risk-Off;
- Selective Opportunity;
- Opportunity Cash Gate;
- Absolute Utility Cash Gate;
- Optimized Allocation;
- Concentrated Allocation;
- Compound Risk Overlay;
- IQN research;
- MongoDB persistence;
- API request schemas and compatibility aliases;
- Paper/live execution contracts;
- model thread override through `MCT_MODEL_THREADS_OVERRIDE`.

The TCC is a reduced scientific reproduction. Its removal of these capabilities
must not be interpreted as a production-engine improvement.

## TCC-specific behavior deliberately not ported

The following belongs to the standalone TCC workflow and is not part of the
MCT API engine:

- Spyder execution sections;
- frozen/local CSV research snapshot management;
- temporary data folders;
- TCC output directory layout;
- standalone XLSX/PNG/SVG artifact generation;
- Portuguese module/function renaming;
- the TCC Control-vs-Soft orchestration script.

## Compatibility

Existing configurations with no `soft_horizon_consensus` settings retain the
Control behavior.

`calendar_anchor_assets` remains accepted so existing MongoDB documents and
API requests continue to validate, although calendar selection is now derived
from actual prepared data.

The public two-value return contract of `prepare_rotation_panel` is preserved
for callers such as the live LightGBM signal path.

## Validation

A dedicated regression suite covers:

- deterministic longest-history calendar selection;
- deterministic calendar tie-breaking;
- generation of per-horizon targets;
- CAGR using the real initial capital;
- inclusive final NYSE market date with UTC daily-bar timestamps;
- equivalence of batched-cache and row-wise utility inference;
- Soft Horizon Consensus remaining opt-in.
