# API v10.8.21 — Exact TCC RAW loader parity

## Why this version exists

API 10.8.20 successfully restored the historical CPU/non-deterministic research
regime but produced exactly the same Control result as 10.8.18/10.8.19:

```text
Control = US$ 5,544,605.11
Fold 1 calibrated margin = 0.0100
```

The recovered TCC history shows that the experiment which reached the ~US$10M
Control was also associated with a market-data transport-only change.

The homologated TCC main downloads each symbol with one Alpaca request:

```python
StockBarsRequest(
    symbol_or_symbols=symbol,
    timeframe=TimeFrame.Day,
    start=2016-01-01T00:00:00Z,
    end=cutoff + 1 day at 00:00:00Z,
    adjustment=RAW,
    feed=SIP,
    limit=10_000,
)
```

The MCT API research loader was not equivalent. It split the historical range
into multiple date chunks and used XNYS session-close timestamps as chunk/end
boundaries.

Even when both paths return 2,692 sessions, the transport contracts are not
identical and can produce different historical payloads/rounding/revisions that
subsequently alter LightGBM calibration.

## Change

For full RAW research refresh only, 10.8.21 now exactly mirrors the TCC loader:

- one request per symbol;
- SIP;
- 1Day;
- RAW;
- UTC start;
- end = locked cutoff + one calendar day at midnight UTC;
- explicit limit = 10,000;
- no date chunking.

Operational/Paper/Live loading keeps the existing chunked loader.

## Audit fields

Each research asset now records:

```text
research_bar_loader = tcc_single_request_v1
research_bar_request_limit = 10000
research_bar_end_mode = cutoff_plus_one_day_utc
research_bar_chunking = false
```

These fields are included in the reproducibility manifest.
