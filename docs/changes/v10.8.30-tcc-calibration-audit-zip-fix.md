# API v10.8.30 — Fold-1 calibration input-audit ZIP compatibility

## Cause

The completed v10.8.28 data parity script writes its generated inner ZIP
with `report.json` at the ZIP root. The v10.8.29 calibration script checked
only archive entries ending in `/report.json`, which cannot match the
root-level member. Local invocation failed with
`ValueError: Input audit ZIP has no report.json.` before the MongoDB or
LightGBM work began. The report itself is present and valid.

## Fix

`_load_completed_audit_report()` accepts exactly one report entry, either
`report.json` at ZIP root or a directory-prefixed `.../report.json`.
It reports a useful error for missing/ambiguous entries, parses JSON as an
object, and preserves the subsequent strict completed-55/55/hash checks.

Regression tests cover root-level ZIP, wrapped-folder ZIP, and missing or
duplicate entries. No production strategy settings, model code, TCC source,
snapshot, Alpaca data or Mongo collections are changed.
