# API v10.8.64 — TCC Control peak-exit persistence fix

## Cause

API v10.8.63 added peak-to-exit diagnostics in the MCT rotation diagnostics module, but the operational Strategy #12 uses the protected TCC v1.0.6 runtime. That runtime executes the vendored scientific engine, whose frozen `tcc_v106_reference/rotation_diagnostics.py` intentionally does not contain the new MCT-only fields.

As a result, completed TCC Control backtests were valid and unchanged, but the saved SELL / FINAL_SELL rows had no `peak_exit_diagnostics_schema_version`. The analytics endpoint therefore returned `peak_exit_analysis.trades = []`, and the Front displayed only the availability box.

## Change

- Keep the vendored TCC v1.0.6 scientific source unchanged.
- After the scientific run completes, enrich the returned trade rows in the MCT operational wrapper using `engine.rotation_diagnostics.enrich_trade_diagnostics`.
- Use the exact `bars_by_symbol` frames supplied to that backtest.
- Persist the enriched trade rows through the existing run-result save path.

## Scientific isolation

This post-processing happens after the TCC simulation is complete. It does not change:

- model fitting;
- policy decisions;
- BUY / SELL timing;
- execution prices;
- fees;
- equity curve;
- ending capital;
- Sharpe;
- drawdown;
- strategy metrics.

It only adds diagnostic fields to the already-computed trades.

## Expected result

A new Strategy #12 backtest executed with API v10.8.64 stores schema-v1 peak-exit fields on SELL / FINAL_SELL rows, allowing Front v10.7.18 to render the Peak proximity and exit timing metrics and charts.

Backtests executed before v10.8.64 are not backfilled from later mutable market data.
