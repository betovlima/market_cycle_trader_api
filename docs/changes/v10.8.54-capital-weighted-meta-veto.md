# MCT API v10.8.54 — Capital-Weighted Meta-Veto

## Objetivo

Tentar aumentar o capital final em relação à v10.8.53 sem alterar a arquitetura
da policy. A única hipótese nova é que decisões históricas com maior impacto
econômico devem ter mais influência no treino da Logistic Regression.

## Referências obrigatórias

A mesma execução deve reproduzir antes da candidata:

- v10.8.44 Liquidity-Aware: `US$ 1,078,635.4115518222`
- v10.8.53 One-shot Meta-Veto: `US$ 1,891,417.6670329159`

Tolerância absoluta: `1e-6`.

Se qualquer paridade falhar, o experimento aborta.

## Única mudança experimental

Modelo permanece:

- Logistic Regression balanceada L2;
- C = 0.25;
- mesmas 9 features;
- mesmo threshold de veto <= 0.35;
- mesmos gates BA >= 0.52 e AUC >= 0.52;
- mesma maturidade `rollout_end_date < test_start`;
- mesma semântica one-shot.

Somente o treino passa a usar:

`w_i = max(abs(delta_capital_fraction_i), 1e-6) / mean(max(abs(delta_capital_fraction), 1e-6))`

Os pesos são calculados separadamente em cada conjunto histórico usado no fit.

A calibração permanece sem peso, para manter comparabilidade do gate.

Não existe:
- expoente ajustável;
- clipping ajustável;
- threshold novo;
- grid search;
- tuning HTTP;
- seleção posterior de features.

## Comparação

O mesmo job executa:

1. v10.8.53 reference, com treino uniforme;
2. v10.8.54 candidate, com capital-weighted training.

A candidata só é considerada melhoria quando:

`candidate_final_capital > v10.8.53_reference_final_capital`

Nenhuma promoção operacional ocorre automaticamente.
