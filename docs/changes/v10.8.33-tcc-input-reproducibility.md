# API v10.8.33 — correction of reproducibility and source-data parity

## Why this is a correction, not another margin search

The closed Fold-1 audit (v10.8.28–v10.8.32) established that the later
TCC-main frozen CSVs and the MCT Strategy #11 archive are **numerically
equivalent** to 1e-12, but not bitwise identical. CLMT's training features
differed at float64 representation level and were sufficient to change its
LightGBM model and the selected Fold-1 margin. Target precision and inference
feature precision did *not* account for that change. The difference does not
prove bad corporate actions, bad price history, or asset identity corruption.

Scientific source-data parity cannot be guaranteed by taking two independent
historical downloads and rounding away differences. Different snapshots can
legitimately result in different fitted models. Therefore we expose one
**explicit immutable data-source choice** for scientific reproduction instead
of changing prices or forcing the original candidate-margin winner.

## Implemented engineering corrections

1. In the **MCT Strategy #12 reference runner only**, opt in to using the
   authoritative, file-hash verified TCC main CSV snapshot. Its manifest
   canonical SHA-256 and all 112 source-file SHA-256 values are verified before
   any model is trained. Asset order, RAW/SIP/1Day contract and cutoff are
   guarded, and the one documented structural identity exclusion (DOC) is
   still applied. The vendored TCC v1.0.6 engine receives those exact parsed
   CSV values with no artificial rounding. No writes are made to the TCC
   repository, files, or Mongo source bars.
2. Strict source provenance in both Control and Soft results: `input_source`,
   `tcc_frozen_snapshot_used`, pinned CSV SHA and distinct data-source commit;
   the scientific engine source tag/commit remains separate.
3. Fixed an actual pandas compatibility bug in MCT research split normalization:
   input OHLCV is cast to float64 before applying fractional split volume
   factors (e.g. 10001 × 3/2). No manual price repair; MCT Mongo RAW values
   already held float64 and remain numerically unchanged.
4. Regression tests verify opt-in default, 112-file manifest contract,
   tamper detection, fractional split normalization and DOC exclusion. One
   integration-style test verifies the frozen path does not call the normal
   Mongo/Alpaca loader.

## Data-source modes and safeguards

`MCT_TCC_V106_INPUT_SOURCE=mct_current` (or unset) is **the unchanged default**:
MCT uses the latest Alpaca-origin Mongo market data with its normal RAW
total-causal protocol and normal refresh behavior.

`MCT_TCC_V106_INPUT_SOURCE=tcc_frozen_main` is a research-only explicit
alternative. It requires
`MCT_TCC_V106_FROZEN_DATA_DIR=<absolute folder ending in dados/pesquisa>`
and verifies immutable manifest
`4e2fd225cc0ea05da56dad8f0628ca989ad332812a5fa3a7dc796b2b8a6d5128`
at TCC **main data commit**
`f9cf29fdb736676d0d3e26780481be99813c602a`. These CSVs were
committed *after* the scientific v1.0.6 **code** tag, so this mode does not
claim that the original ~USD 10M TCC run used the same bytes.

The two Control/Soft variants in one MCT job receive the exact same in-memory
frames. No risk policy, LightGBM parameters, strategy mode, TCC source or
market prices were changed. This env opt-in belongs only in a separately
launched local research API process and must **not** be enabled globally in
Railway/production. An already-running API process will not inherit new
PowerShell environment variables.

## Usage (PowerShell at the API repo root)

```powershell
git fetch origin
git switch main
git pull --ff-only origin main
git switch --track origin/research/v10.8.33-tcc-input-reproducibility
$env:PYTHONPATH = "src"

# Normal operational research uses refreshed MCT data:
Remove-Item Env:MCT_TCC_V106_INPUT_SOURCE -ErrorAction SilentlyContinue
Remove-Item Env:MCT_TCC_V106_FROZEN_DATA_DIR -ErrorAction SilentlyContinue

# Only for a separate LOCAL Strategy #12 scientific parity run, set the
# following variables in the API SERVER process before starting it:
$env:MCT_TCC_V106_INPUT_SOURCE = "tcc_frozen_main"
$env:MCT_TCC_V106_FROZEN_DATA_DIR = "$env:USERPROFILE\tcc_frozen_audit\dados\pesquisa"
Test-Path "$env:MCT_TCC_V106_FROZEN_DATA_DIR\manifest.json"
```

The research job then runs Strategy #12 (Control/Soft) through the same UI
but marks both results as `tcc_frozen_snapshot_used=true` and includes the
data snapshot SHA. Do not compare its capital with a refreshed MCT run as if
both had the same data source. Reset the variables and restart that
research-only API process before normal MCT use.

## Closure criteria

- CI passes on the branch head.
- One optional local scientific parity run can verify both result variants
  share the exact pinned dataset; it should not be used for Winner promotion.
- Ongoing Strategy #12 evaluation uses its separate refreshed MCT source,
  versioned data signatures and OOS metrics. No more numerical branch
  exploration is a prerequisite for that work.

This fixes source identity and the concrete integer-volume bug. It does not
promise exact reproduction of any historical capital number from a different
or unavailable source snapshot. Document the research/operational comparison
with the two source identifiers rather than treating decimal-equivalent
histories as interchangeable bitwise datasets.
