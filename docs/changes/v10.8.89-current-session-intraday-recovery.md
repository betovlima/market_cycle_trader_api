# API v10.8.89 — U67 current-session intraday manual recovery

## Goal

Make **Reanalyze Winner for today** represent the market state of the
currently open XNYS session instead of replaying only the previous completed
daily session.

The public admin endpoints do not change:

- `POST /api/admin/trader-control/manual-recovery/prepare`
- `POST /api/admin/trader-control/manual-recovery/execute`

## Data contract

For the protected TCC U67 Winner, manual reanalysis while the regular market is
open now uses two layers:

1. full fresh U67 historical daily snapshot through the latest safely completed
   XNYS session, using the existing RAW/SIP + corporate-action/split-normalized
   contract;
2. one synthetic in-progress daily observation for the current session,
   aggregated from Alpaca `alpaca_live_feed` 1-minute bars (the protected U67
   profile uses IEX).

The in-progress row is used only as the **prospective scoring observation**.
Training and calibration remain behind the existing U67 purge window and do not
train on the incomplete current-session bar.

The synthetic observation uses:

- open: first regular-session 1-minute open;
- high: maximum high observed so far;
- low: minimum low observed so far;
- close: latest completed 1-minute close;
- volume: cumulative observed volume;
- VWAP: volume-weighted aggregation when available;
- trade_count: cumulative observed trades when available.

If any eligible U67 asset has no current-session live bar, preparation fails
closed. No fallback data source or invented price is used.

## Manual plan semantics

During an open regular session:

- `decision_date` is the current XNYS session;
- `execution_session` is the same current XNYS session;
- `historical_cutoff` remains the previous safely completed daily session;
- the plan records `analysis_mode=current_session_intraday`,
  `analysis_timestamp_utc`, live feed/timeframe and intraday freshness
  metadata.

This replaces the previous v10.8.88 behavior where the manual plan was a
same-day execution of a decision based only on the prior completed daily bar.

## Order safety

Reanalysis still **does not submit an order**. It only produces a
`status=prepared` Paper plan.

The existing explicit execution endpoint still performs the order path and
retains:

- regular-market-open requirement;
- Winner/model identity binding;
- MongoDB/Alpaca position reconciliation;
- open-order conflict checks;
- single-executor claim;
- sell-fill before buy;
- contingency handling for a completed sell followed by a failed buy;
- paused/stopped/exit-only controls.
