## Fixed architecture and exact target
CPU-only pooled TCN: all 55 eligible assets share one small model PER chronological fold; not 55 deep networks. 40 completed-session window, 12 predeclared *causal* feature columns (return_1, return_5, return_20, return_60, vol_20, vol_60, ema_distance_20, ema_distance_50, rsi_14, atr_pct_14, channel_position_50, volume_zscore_20). Five Conv1d residual dilated causal blocks, 16 hidden channels, dilations 1,2,4,8,16, kernel size 3 and right-padding removal. Receptive field 63 sessions. Dropout 0.10. Head estimates the *unchanged* TCC target forward_risk_adjusted_utility with original 5/10/20/40/60 weights and downside/drawdown penalties. Not a direct dollar profit target, reinforcement learning, or demonstrated ensemble.

Predeclared overlap control: use every third training window (stride=3, per symbol), retain every eligible calibration/OOS observation. No outcome-dependent sampling. Predeclared hyperparameters: CPU, seed 42+fold; AdamW, learning rate 0.001, weight decay 0.01, batch 256, SmoothL1 loss, gradient norm <=1, maximum 8 epochs, validation patience 2, train-only mean/std scaler, target standardized train-only, feature range [-8,8] and normalized label range [-5,5]. Predictions are inverse-scaled and bounded to [-3,3]. Fixed predeclared switch margin 0.0025, not selected by OOS. Torch RNG protected by fork_rng; no global TCC monkeypatch.

## Temporal protocol and leakage barriers
Original frozen panel/calendar/folds: 55 assets, 3 chronological OOS folds and 1554 sessions. For each fold train the calibration network only on historical dates BEFORE the train cutoff, with complete 60-session target maturity strictly before calibration starts. Validate only on chronological calibration dates whose complete 60-session label matures before test starts; calibration selects *number of epochs*, not architecture or OOS settings. Refit a new network from scratch with those fixed epochs on expanding final-fit dates, using only labels whose maturity timestamp is strictly before the first OOS session. Both scalers are fitted independently using only their corresponding training dates/labels. No overlapping-window label maturity into test. TCN inference uses the t-window's causal features only and does NOT call the vendored future-session open/close availability filter to predict a candidate.

For each OOS decision at completed session t, obtain 55 TCN utilities; the existing v10.8.44 prior-close-capacity overlay applies the exact 10% x median(last20 volume) x completed close transformation using actual portfolio state. The original TCC utility policy function is reused with a cache of TCN scores and fixed switch margin. The v10.8.42 accounting is reused unchanged: cap fills ex post by minimum of previous-volume and realized next-session volume at 10%, assumed adverse spread and impact, original fees, integer shares, partial holds, residual CASH and no terminal forced liquidation. No future day price or volume in TCN features, scaler, signal or liquidity forecast. The daily volume at execution date is used EX POST for fill modeling only.

## Interpretation and next steps
First deep-learning experiment is a predeclared SUPERVISED TCN alternative utility estimator, not a proof of causal profit, nor a finished contextual counterfactual policy. The original utility label is future-facing by design but only labels whose future is completely in the past relative to fitting may enter training/validation. The original Control's inherited next-bar availability check is not used to generate TCN signals; reported old baselines retain their historical implementation caveat. A future separate hypothesis for contextual marginal capital, multi-asset interactions or joint execution optimization must get its own new version, with a genuinely unobserved future OOS, without choosing a model retrospectively by this historical test. A 2026-09-28 snapshot cannot establish unseen forward results beyond that date.

Any capital output is model-based, marked-to-market and non-liquidated. Daily OHLCV and assumed price impact do not guarantee actual broker fills. Preserve source TCC, original Control, strategy 28, original Winner, production scheduler and real orders.

85,470 score rows are complete: exactly 55 assets on every one of 1,554 decision dates, no duplicates. 82,225 rows have mature 60-session retrospective labels and 3,245 final-fold rows are correctly flagged unmatured at snapshot cutoff.

Reported mature-OOS metrics:

- The target is positive on **72.305%** of mature rows, so an always-positive sign guess slightly *beats* TCN sign accuracy.
- A single constant median predictor yields MAE **0.167924**, better than TCN 0.169442.
- A single constant mean predictor yields RMSE **0.219265**, better than TCN 0.220872.
- TCN prediction standard deviation is only 0.03257 vs target 0.21927; 99.72% of TCN mature predictions are positive. Prediction mean 0.11996 is close to realized target mean 0.12439.

Its lower error relative to zero is mostly explained by estimating the positive unconditional center of the target. Calibration Huber loss selected 4/3/4 epochs by folds but that loss is not aligned with the portfolio's primary need: correctly ranking candidates.

### Scientific interpretation

Do **not** tune TCN depth, features, loss, epochs, margin, target or sampling by choosing whichever retrospective variation raises the same OOS capital. The current v10.8.45 result falsifies the narrow hypothesis that this *predeclared pooled Huber-regression TinyTCN* is a useful replacement utility estimator under this design.

The next Deep Learning hypothesis, if pursued, should be versioned separately and change the **learning objective**, not merely make the network larger. The portfolio decision requires cross-sectional ranking. Candidate research options that can be preregistered include:
1. pairwise/listwise ranking loss within date, with strictly chronological label maturity;
2. a contextual paired target such as candidate-vs-incumbent marginal utility/capital advantage;
3. multi-task temporal representation + ranking head, with liquidity/current-position context passed explicitly;
4. preserve a simple constant/rank baseline and LightGBM as mandatory predictive controls.

Any such design is a **new conceptual experiment** and should use validation/calibration dates only for design choices, leaving a later untouched period for confirmation. No automatic promotion. The current result does not change TCC, v10.8.44, Control, Winner, production or orders.
