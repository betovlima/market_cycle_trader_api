# API v10.8.63 — Peak-to-exit diagnostics

## Objective

Measure, for every closed portfolio position, how close the strategy exited to the best intraposition price that was actually observable while the position was held. The feature is diagnostic only: it does not change model training, TCC Control parameters, rotation decisions, Paper/Trader execution, Winner state or order submission.

## Timing contract

- Normal `SELL` executes at the exit-session open. The held-period peak therefore uses daily `high` values from entry through the previous session and never uses the exit-session intraday high.
- `FINAL_SELL` is final-close bookkeeping. Its held-period peak includes the final session.
- Post-exit windows start on the exit session for a normal `SELL` and on the following session for `FINAL_SELL`.
- Post-exit 5/10/20-session metrics are emitted only when the complete horizon exists. Partial windows at the end of a backtest remain null.

## Frozen metrics

Each closed trade persists:

- `peak_price_while_held`
- `peak_timestamp_while_held`
- `exit_distance_from_peak_pct`
- `peak_capture_pct`
- `max_runup_pct`
- `days_from_peak_to_exit`
- `post_exit_peak_5d_pct`
- `post_exit_peak_10d_pct`
- `post_exit_peak_20d_pct`
- `peak_exit_diagnostics_schema_version=1`

The values are calculated inside `engine/rotation_diagnostics.py` from the exact OHLC frames used by that backtest and persisted with the trade. Analytics never recompute these values from a later Alpaca snapshot.

`exit_distance_from_peak_pct` is floored at zero. A gap-up exit above the previous held-session high is therefore a zero-distance exit. `peak_capture_pct` is price-based, bounded to 0–100%, and compares realized entry-to-exit price gain with the maximum held-period run-up.

## Analytics API

`GET /api/analytics/backtests/{job_id}` now includes `peak_exit_analysis`:

- consolidated summary;
- per-asset aggregation;
- frozen closed-trade observations for charting.

Old jobs without schema v1 diagnostics return an empty peak-exit analysis instead of being recomputed against mutable market history.

## Regression coverage

`tests/test_peak_exit_diagnostics.py` covers:

- no exit-session look-ahead for a normal sell;
- inclusion of the final session for final-close liquidation;
- gap-up exit capped at 100% capture / 0% distance;
- complete-horizon requirement for post-exit metrics;
- per-asset aggregation and exclusion of legacy rows without schema v1.

Existing `maximum_favorable_excursion`, `maximum_adverse_excursion` and `profit_capture_ratio` are kept unchanged for backward compatibility.
