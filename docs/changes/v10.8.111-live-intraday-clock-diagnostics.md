# API v10.8.111 — Live intraday clock & fail-closed execution window

**Branch:** `fix/v10.8.111-live-intraday-clock-diagnostics`
**Base:** `main` commit `11512d230b86353a3ae4e33b25b60e301b8bf068`
**Scope:** MCT operational only. No TCC, model, Strategy #30, universe or parameter changes.

## Incident motivating the change

On 2026-10-19 the Live U77 Winner historical snapshot for 75 assets completed
after approximately 79 seconds, but opening recalibration then failed at
`intraday_bars` with only `RuntimeError` exported. The exact exception
message, asset and feed are **not** available in the exported audit. We cannot
claim that AMS or the SIP fallback was the concrete cause.

The old code passed `clock.timestamp` captured **before** historical
download into the intraday reader. Around a 09:30:46 open, that timestamp may
not even contain one completed minute, although wall clock was already ~09:32.
The Paper path shares the underlying intraday data aggregation function.

## Fixes

1. Live checks there is a completed regular-session 1-minute bar before
   refreshing historical data. Early polls remain `signal_prepared`, return
   `waiting_for_intraday_data`, and do not claim session or submit orders.
2. **After** historical refresh Live re-reads the Alpaca broker clock.
   Current intraday scoring uses that refreshed time rounded down to the last
   completed minute **only in the Live caller**. The shared intraday collector
   (also called by Paper) remains byte-identical to `main` and no Paper
   decision/clock behavior is changed by this release.
3. The original IEX → complete-universe SIP → uniform 20-minute delayed SIP
   fallback is deliberately **preserved**, with no mixing feeds or dropping
   an illiquid symbol. If delayed SIP is too early, Live defers the next
   attempt until at least 09:51 NY without re-downloading on intermediate
   scheduler polls. A new attempt downloads fresh history again by design.
   This does not alter the Paper retry logic.
4. The independent Live 30-minute order window is enforced before recalibration,
   after historical refresh, after model completion and **before each** broker
   sell/buy leg. All expiration paths are no-order/fail-closed. A previously
   submitted sell cannot authorize a late buy: reconciliation is required.
5. Live events retain safe `error_code`, `symbol`, `feed`, `cutoff` and
   `retry_after` fields when known. Raw provider errors and credentials are
   never exported. The Live session status exposes the recognized error code,
   symbol and feed for diagnosis.
6. For existing deployments the Live execution window is 30 minutes after
   regular NYSE open, independent of Paper execution settings. No broker orders
   are dispatched by this branch or by its tests.

## Verification

Run from the repository:

```bash
python -m unittest discover -s tests -p "test_*.py" -v
```

All tests mock broker writes. The simulations include incomplete first minute,
mid-download clock advancement, post-training expiration, expired order
submission, missing IEX symbols and the SIP entitlement fallback.

**Rollout:** No automatic deployment or merge. Before approval, check GitHub
Actions for the final commit, review Live mode, inspect current broker orders,
and ensure the session is not already running. A normal new session is preferred
to deploying a changed scheduler mid-session.

**Limits:** No historical reconstruction of the exact 2026-10-19
`RuntimeError` from the original sanitized event file is possible. This
change improves attribution for future failures. The 30-minute execution
window may intentionally expire when data are only available via delayed SIP
or training takes too long; it must not be bypassed to trade.
