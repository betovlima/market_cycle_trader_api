# API v10.8.18 — Fresh RAW + deterministic research parity

## Why v10.8.18 exists

API 10.8.17 corrected the research protocol to use Alpaca RAW bars, local split
normalization and structural-identity exclusion. A real Simulation nevertheless
finished near US$ 5.54M while the homologated TCC research line reached about
US$ 10.08M.

The mismatch was reproduced against the historical TCC research artifacts.

Two TCC experiments on the same strategy family are especially important:

- `raw_split_soft_horizon_consensus`: Control ≈ US$ 5.55M;
- `soft_horizon_7m_direct_alpaca_v10880`: Control =
  US$ 10,082,425.91.

The latter explicitly records:

```text
change_scope = market_data_transport_only
source = alpaca_direct_http
bars = fresh Alpaca RAW SIP daily bars
deterministic_execution = true
LightGBM n_jobs = 1
```

The 10.8.17 MCT run matched the earlier ~US$ 5.55M behavior:

- fold 1 calibrated switch margin = 0.0100;
- fold 2 calibrated switch margin = 0.0100;
- fold 3 calibrated switch margin = 0.0000.

The fresh direct TCC run instead uses:

- fold 1 calibrated switch margin = 0.0000;
- fold 2 calibrated switch margin = 0.0100;
- fold 3 calibrated switch margin = 0.0000.

The first OOS divergence is already visible on 2020-07-28. Both engines rank
MGM above CXW with essentially the same model scores, but the 0.0100 MCT margin
blocks the rotation that the homologated experiment accepts.

## Root causes addressed

### 1. Simulation did not necessarily replace the complete RAW history

10.8.17 separated `adjustment=raw` from the old adjusted cache, but if RAW
documents already existed in MongoDB the Simulation could reuse them and only
refresh the tail when coverage was stale.

That is not equivalent to the TCC direct-Alpaca experiment, which downloaded the
complete RAW history again.

Starting with 10.8.18, research Simulation with
`raw_total_causal_v1` and `backtest_bootstrap_missing` uses:

```text
research_market_data_refresh_mode = full
```

For every configured asset:

1. download the complete locked RAW history from Alpaca;
2. only after a successful full download, replace the Mongo rows inside the
   locked research window;
3. read the new RAW rows back from Mongo;
4. apply the homologated local split normalization;
5. run the backtest.

Corporate Actions are also downloaded as a complete fresh snapshot during
Simulation instead of silently reusing an already-covered cached document.

Model Tuning remains database-only and never performs these downloads.

### 2. Research LightGBM was not locked to the homologated deterministic regime

The 10.8.17 exported effective config contained:

```text
deterministic_execution = false
LightGBM n_jobs = -1
```

The homologated direct-Alpaca experiment used:

```text
deterministic_execution = true
numeric_thread_limit = 1
LightGBM n_jobs = 1
early_stopping_enabled = false
```

10.8.18 forces those settings only in the effective Research/Simulation
configuration. The operational Strategy profile remains unchanged.

When deterministic execution is enabled, the LightGBM fitter also hard-locks
`n_jobs=1` so `MCT_MODEL_THREADS_OVERRIDE` cannot accidentally make a
reproducibility run multithreaded.

## Operational versus research configuration

The Strategy document can still contain operational settings such as:

```text
alpaca_adjustment = all
deterministic_execution = false
LightGBM n_jobs = -1
```

The Simulation effective configuration becomes:

```text
alpaca_adjustment = raw
research_market_data_protocol = raw_total_causal_v1
research_market_data_refresh_mode = full
deterministic_execution = true
numeric_thread_limit = 1
LightGBM n_jobs = 1
early_stopping_enabled = false
```

Paper/Live behavior is not changed by this research-effective transformation.

## Data lifecycle

Simulation:

```text
fresh full Alpaca RAW
      +
fresh full Corporate Actions
      ↓
Mongo RAW research cache replaced for locked window
      ↓
homologated split normalization
      ↓
structural identity exclusion
      ↓
Control backtest
      ↓
certified effective config + market-data signature
```

Model Tuning:

```text
certified Simulation
      ↓
freeze processed market-data snapshot
      ↓
database-only candidates
      ↓
LHS + CARO/BoTorch
```

No tuning candidate accesses Alpaca.

## Homologated split/dividend methodology

Parity remains defined against the homologated TCC main:

```text
betovlima/tcc_mba_usp_data_science_analytics
main commit:
f9cf29fdb736676d0d3e26780481be99813c602a
```

Research bars are:

- Alpaca SIP 1Day RAW;
- locally normalized for forward/reverse splits using the homologated
  pre-ex-date price/volume unit transformation;
- not back-adjusted for dividends;
- subject to structural identity exclusion.

Dividend events remain audit information and do not modify model OHLCV,
features or targets.
