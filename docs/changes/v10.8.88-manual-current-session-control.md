# MCT API v10.8.88 - manual current-session control

## Objective

Make the Manual Recovery controls usable for the current regular session even
when the scheduler did not create a Paper run for that session.

This is especially useful after a mid-session Winner promotion, when the new
Winner is valid but the historical scheduler state does not contain a run for
today.

## Behavior

`Reanalyze Winner for today` no longer requires a scheduled Paper run.

When the regular market is open, the administrator may request a fresh
current-session analysis. The runtime:

1. reconciles Mongo Paper state with Alpaca;
2. refreshes the Winner market data using the normal live path;
3. trains/calibrates the current Winner using only completed daily bars;
4. uses the current regular session as the execution session;
5. uses the current session 09:30 America/New_York regular open as the plan
   open timestamp when no scheduler run exists;
6. creates a prepared Paper plan without submitting any order.

`Retry plan on Alpaca` becomes available after a valid prepared plan exists
or when a recoverable contingency exists.

## Safety restrictions retained

The change deliberately does not remove the safeguards that prevent duplicate
or unsafe orders:

- reanalysis is available only while the regular market is open;
- an executing, recovering or already executed current-session plan cannot be
  replaced;
- manual order execution still requires a prepared/recoverable plan;
- manual execution still reconciles Paper state with Alpaca and checks for
  conflicting orders;
- paused/stopped Trader modes still block normal manual execution;
- exit-only mode still blocks new entries;
- execution still requires explicit UI confirmation;
- no historical executed plan is overwritten.
