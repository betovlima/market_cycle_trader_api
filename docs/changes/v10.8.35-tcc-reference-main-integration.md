## Production installation: research-only

After this integration is merged, deployed and authenticated as an administrator:

`POST /api/research/tcc-v106/strategy`

No JSON body is required. The installer is idempotent by engine binding and TCC source commit. It creates or reselects the reference Strategy **only for Research**, leaving Winner and Model Tuning selections unchanged. The production strategy number is allocated by its catalog, **not hard-coded to #12**. Protected Trader Winner #27 and the existing paper portfolio remain intact. Ordinary `POST /api/jobs` / Backtest Simulation then executes both Control and Soft Horizon Consensus. A reference-engine Strategy cannot be promoted to Trader using the incompatible live engine. The TCC Git repository itself is unchanged.

## Data contract

Default `MCT_TCC_V106_INPUT_SOURCE` (unset or `mct_current`) uses a **fresh full Alpaca RAW/SIP download** for each new normal reference Simulation, then updates and loads MongoDB cache. Corporate actions are refreshed and processed according to the research RAW protocol. The latest safely completed XNYS session (regular or early close plus a 20-minute buffer) is resolved at queue time, independently of the stale cached cutoff. Missing data through that cutoff fails explicitly. Every result records source, effective cutoff and market-data signature. This does not imply continuous intraday refreshing.

Explicit `tcc_frozen_main` is a different SHA-verified local scientific run fixed to 2026-09-17 and **must not be enabled globally in Railway**. Model Tuning remains immutable/database-only; Paper/live Trader data and decisions are not switched to the research path.
