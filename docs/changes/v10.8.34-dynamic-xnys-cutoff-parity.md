# API v10.8.34 — MCT × TCC reference code audit and dynamic XNYS cutoff

## Scope, identity and authoritative references

Compared the published TCC tag `v1.0.6`, the TCC `main` at
`f9cf29fdb736676d0d3e26780481be99813c602a`, and the MCT API reference
branch based on v10.8.33. TCC repository, tag, tracked snapshot and CSV files
are **unchanged** by this release.

The **12 MCT vendored engine source files** under
`src/market_cycle_trader_api/tcc_v106_reference/` have **exactly the same Git
blob SHAs** as the corresponding `tcc_engine/` sources at TCC tag
`v1.0.6`, commit `c0d71772092f0c26c9f28f0211b9933e9c396b95`.
The engine, fixed five horizons and weights, LightGBM settings, Control and
Soft methodology, costs and calibration grid are preserved. The independent
TCC `main` moved the model to `engine/` modules; those current files are
not byte-identical to the earlier tag, although the inspected key
hyperparameters and policy thresholds agree. Do not claim unconditional
parity between two *different versioned implementations* or between two
different source snapshots.

The pinned TCC scientific analysis end remains **2026-09-17**. Its frozen
later-main dataset SHA
`4e2fd225cc0ea05da56dad8f0628ca989ad332812a5fa3a7dc796b2b8a6d5128`
does not establish historical v1.0.6 dataset-byte identity.

MCT operational Strategy #12 uses Alpaca RAW/SIP, applies the TCC split
normalization, and caches data in Mongo. The v10.8.28–v10.8.32 audits found
the specific CLMT feature representation issue and established 55-asset
numerical input parity (tolerance 1e-12) for the old cutoff—not byte
identity. The v10.8.33 optional immutable TCC-main source remains research-
only. The TCC current main's optional temporary-data runner uses a
wall-clock/16:15 ET heuristic and asks Alpaca to resolve the last available
session; it is **not** the same exchange-calendar cutoff resolver as MCT.
We intentionally did not modify that separate TCC repository.

## Corrected problems

1. The installed MCT Strategy #12 profile had a hardcoded `end_date` of
   2026-09-17 inherited from the scientific tag, so new operational runs
   could not extend beyond that day. New profile defaults no longer have
   a fixed end date, and the **queue-time source-aware execution-window
   override** also handles previously installed profiles without altering
   their stored documents. Explicit `tcc_frozen_main` runs retain the
   precise scientific 2026-09-17 window.
2. Before refreshing Alpaca, the generic Simulation resolver previously
   restricted the requested cutoff to the earliest shared Mongo cached
   session, so a stale cache could prevent refreshing *past the stale
   cache*. New bootstrap/full-refresh Simulations now resolve the market
   target without this cap; the existing cached-common-session behavior
   remains available for read-only calls. If Alpaca fails to supply complete
   data through the chosen cutoff, the job fails visibly rather than
   silently reporting an earlier analysis end.
3. Uses the **XNYS regular/early-close calendar plus 20-minute data
   availability buffer**, so the cutoff is always a completed exchange
   session, not the wall-clock date. E.g. Saturday 2026-09-26 => Friday
   2026-09-25. During the Friday session and 0–19 minutes after closing,
   use Thursday until the bar is safe; an NYSE holiday skips to the previous
   session.
4. The optional reference-data source selected at queue time is now
   persisted inside `BacktestExecutionRequest.tcc_reference_input_source`
   and used by the reference worker. Changing an environment variable
   after queueing cannot silently switch a new job from current MCT data
   to frozen TCC CSV (or vice versa). Both completed Control/Soft variants
   record source and effective cutoff in the job/result provenance.

## Guarantees and intentional differences

| Path | Cutoff | Data |
|---|---|---|
| MCT Strategy #12 normal Simulation | Latest safely completed XNYS session | Full Alpaca RAW/SIP refresh, Mongo cache updated, then loaded |
| MCT #12 explicitly frozen TCC parity | 2026-09-17 | SHA-verified later TCC-main CSV snapshot, read-only |
| TCC frozen research (unchanged) | 2026-09-17 | Git-versioned CSV snapshot |
| TCC current temporary experiment (unchanged) | Its own 16:15 ET heuristic + actual provider availability | Independent temporary Alpaca CSVs |
| MCT model tuning | Pinned immutable market-data snapshot / Mongo only | No Alpaca download |

A later cutoff changes fold windows and can change OOS outcomes. Do not compare
capital across two different cutoffs or snapshots as if the inputs matched.
No margin forcing, historical series repair, CLMT exclusion or model changes
were introduced.

## Tests

`tests/test_tcc_v106_dynamic_xnys_cutoff.py` covers Saturday/Sunday,
intraday and the 20-minute post-close bar-availability buffer, holidays,
stale cached session vs new full refresh, existing Strategy #12 profiles
and immutable reference-data source. The existing SHA test guards the full
original vendored engine. Check the final GitHub Actions run at this branch's
HEAD for CI status; a passing CI is not proof that fresh live Alpaca data for
all assets has already been obtained.

## PowerShell commands

```powershell
git fetch origin
git switch main
git pull --ff-only origin main
git switch --track origin/research/v10.8.34-dynamic-xnys-cutoff-parity
$env:PYTHONPATH = "src"

python -m unittest discover -s tests -p "test_tcc_v106_dynamic_xnys_cutoff.py" -v
python -m unittest discover -s tests -p "test_tcc_v106_input_reproducibility.py" -v
```

Start a **new** Strategy #12 Simulation Backtest to obtain a new job with
the current exchange cutoff. Jobs already queued retain their original
immutable request. In normal MCT mode leave
`MCT_TCC_V106_INPUT_SOURCE` unset or `mct_current`.
Do not globally enable `tcc_frozen_main` on Railway/production.
The request's `analysis_end_date` and the results' market-data signature
must be inspected before comparing against older reports.
