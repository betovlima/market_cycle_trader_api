# MCT API v10.8.138 / Front v10.7.59: solicitar Winner diário no Live

## Motivo
A interface Live deixou de oferecer o comando identificado pelo usuário como **Recalcular Winner usando histórico diário**. A UI de reanálise existente na página System Settings era exclusiva do Paper. O endpoint Live de reanálise intradiária foi desativado deliberadamente. A rotina Live vigente calcula a Winner com **candles diários completos do pregão anterior (D−1)** depois do fechamento; a posição é revalidada na abertura e o sinal pode ser executado automaticamente se o Live estiver ATIVO.

## Implementação e semântica
- `GET /api/live-market/winner/daily-recalculation/status` (Admin): consulta somente a conta Live canônica, calendário XNYS, relógio broker e o estado persistido da sessão. Informa data de decisão D−1, próximo pregão e elegibilidade.
- `POST /api/live-market/winner/daily-recalculation/request` (Admin, confirmação obrigatória `REQUEST_DAILY_SIGNAL_NO_ORDERS`): idempotentemente arma a próxima sessão **somente** quando seu sinal diário estiver ausente, a bolsa estiver fechada, a janela segura do candle já tiver transcorrido, e o Live estiver ativo/exit_only. Registra a solicitação na própria sessão canônica. O agendador Live existente fará a preparação usando o algoritmo histórico já consolidado; a chamada HTTP **não** inicia treinamento de longa duração nem chama o broker para submeter/cancelar ordens.
- Uma decisão diária já válida, já executada ou em reconciliação não pode ser substituída pelo botão. Um sinal em preparação não é reiniciado. A própria sessão é protegida contra duplicação pelo `LIVE_RUNS` e validação do account_id.
- O comando **não envia uma ordem por si**, mas o sinal produzido continua sujeito à **execução automática na próxima abertura** pelo motor Live existente, quando o modo estiver ATIVO. Isso é informado no diálogo de confirmação e no painel.
- Os usuários Trader OAuth não recebem o botão, nem acesso a endpoints Admin. A função continua somente Admin Live, sem alterar Paper, modelo, credenciais, executor, ordem nem decisão existente.
- O monitor Live de workflow já expõe tentativas e fases a cada 15s, que podem ser acompanhadas após a solicitação.

## Limitações deliberadas
Não é um recálculo forçado/replay de uma decisão já validada. Reanalisar uma decisão pronta exige uma comparação de pesquisa isolada do sinal operacional, para não alterar ordens do dia. Também **não** é uma análise intradiária ou uma tentativa de negociação fora do pregão, nem substitui a estratégia atual de uma avaliação/rotação por dia.

## Validação
Testes sem credenciais reais com mocks de relógio Alpaca em período regular, status válido, pedido duplicado, Live pausado, sessão executada e verificação de ausência de ordens. Teste de UI garante montagem somente no Live Admin e não no Trader.
