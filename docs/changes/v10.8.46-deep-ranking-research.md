# MCT API v10.8.46 — Deep Pairwise Ranking + Control Utility

## Why this experiment exists

The frozen scientific Control remains the primary model benchmark:
**USD 5,887,904.38** from USD 10k. The v10.8.42 execution-constrained
Control is a separate feasibility path at **USD 528,709.78**. The
v10.8.44 Liquidity-Aware policy recovered part of that gap to
**USD 1,078,635.41**. The first Deep Learning hypothesis in v10.8.45
failed badly at **USD 68,345.26** and showed near-zero ranking skill
(Spearman ~0): the pooled TinyTCN regression mostly learned the
unconditional mean of forward utility rather than the cross-sectional
ordering needed to choose one asset among 55.

v10.8.46 therefore changes the *learning objective*, not merely the
network size. This is a new conceptual research mode:
`MCT_RESEARCH_DEEP_PAIRWISE_RANK_LIQUIDITY_V1`.

## Fixed hypothesis before running this OOS

Deep Learning learns only:
> for the same completed decision date, which candidate should rank
> above another candidate?

Training loss is all-pairs logistic ranking over same-date assets:

`softplus(-sign(U_i-U_j) * (S_i-S_j))`

where `U` is the original frozen scientific
`forward_risk_adjusted_utility` and `S` is the neural rank score.
Exact target magnitude is not regressed and score translation does not
matter.

The temporal encoder stays deliberately small and comparable to
v10.8.45: causal TinyTCN feature extractor with the same 12 causal
features and 40-session history. Fixed training choices:
- CPU only;
- every third training date to reduce extreme overlap;
- at least 25 valid assets on a ranking-training date;
- maximum 6 epochs, patience 2;
- AdamW learning rate 0.001, weight decay 0.01;
- chronological calibration only for epoch count;
- all 60-session labels must fully mature before calibration/test;
- fold-specific feature scaler fitted only on historical training dates.

No HTTP parameter can change architecture, loss, epochs, learning rate,
margin or universe.

## Hybrid policy: Deep Learning ranks, Control decides whether it is tradable

The Deep Ranker does **not** create its own absolute utility scale.

For each OOS date the original fold-specific LightGBM Control is trained
and calibrated exactly as before. Its utility cache is then passed
through the already-audited v10.8.44 prior-close liquidity overlay.
That LightGBM+liquidity utility retains responsibility for:
- CASH / positive-utility eligibility;
- minimum expected edge;
- minimum holding guard;
- calibrated switch margin;
- absolute score magnitude.

The Deep Ranker only orders the candidates whose LightGBM+liquidity
utility is above CASH. If the Deep Ranker's top candidate does not pass
the original Control absolute entry/switch rule, the policy does not
skip to a lower-ranked candidate merely because its LightGBM number is
larger. This prevents the new model from silently reverting to a
LightGBM rank after the neural choice fails the gate.

The actual portfolio still uses the exact v10.8.42/v10.8.44 execution
model: whole shares, no leverage, 10% capacity based on prior known
volume and ex-post realized execution-day volume, assumed spread/impact,
original fees, residual CASH and no forced final liquidation.

### Ranking model did not establish useful validation or OOS skill

Calibration pairwise accuracy by fold was 50.28%, 47.92%, 51.80% with chosen epochs 1/2/1. This already showed no robust pre-OOS ordering signal.

Mature historical OOS:
- pairwise accuracy 50.7379% over 2,220,075 within-date pairs;
- mean daily Spearman +0.02154; median +0.02114;
- fold Spearman +0.03118 / -0.00515 / +0.03917;
- predicted top candidate's realized percentile averages 52.80% (random ranking expectation with 55 ranks is ~50.91%);
- exact top-realized winner hit rate independently computed at ~2.81%.

Thus the v10.8.46 Deep Ranker is close to random cross-sectional ordering. It should not replace Control's candidate ordering.

### The hybrid policy also became excessively sticky

Compared with v10.8.44, v10.8.46 changes the actually held asset on 1,233/1,554 sessions (79.34%). Yet only ~17.2% of policy signals equal the neural ranker's instantaneous #1; on ~92.1% of sessions the signal remains the previous held asset, versus ~79.0% under v10.8.44. Capital rotations fall from 320 to 119.

This is an expected consequence of the predeclared hybrid rule: Deep Learning may rank a candidate first, while the original LightGBM absolute utility can fail the switch-margin gate. The policy then keeps the incumbent rather than falling through to another high-LightGBM candidate. With a near-random neural ordering, this simultaneously destroys the original Control rank information and increases incumbent stickiness.

Neural top equals the original raw LightGBM top on only ~3.08% of mature dates and the v10.8.44 adjusted-best candidate on ~3.02% of all OOS dates.

Selected-asset days are concentrated in LKFT 164, TSLA 140, APD 140, RACE 117, MKSI 103 and PXLW 100. Descriptive equity log-return attribution (not causal PnL decomposition) identifies CORT, YANG, PXLW and LKFT among major negative held-asset contributions. Largest individual held-run declines include CORT 2025-12-30→2026-01-23 (~-43.7%), CLMT 2025-02-19→2025-03-11 (~-33.1%), MKSI 2026-07-09→2026-09-25 (~-25.9%), YANG 2024-09-20→2024-09-25 (~-25.1%) and PXLW 2024-09-26→2024-09-27 (~-19.6%).

### Scientific conclusion

v10.8.46 falsifies the second narrow Deep Learning hypothesis: a stand-alone pairwise neural ordering signal does not justify overriding the original Control ordering on this design. This does **not** show that Deep Learning cannot add value to MCT. It shows that replacing a strong Control policy with a weak neural rank signal is destructive.

Do not tune pairwise network size/loss/features/margins against this same OOS.

If Deep Learning continues, the next hypothesis should preserve Control as the default action and learn only an **incremental decision**:
- meta-label / veto: should the original Control proposed rotation be accepted or rejected?
- residual correction: neural model predicts a bounded delta/confidence added to Control utility rather than replacing its order;
- contextual candidate-vs-incumbent marginal advantage using paired counterfactual execution outcomes;
- any neural override must be selected/calibrated only on pre-OOS calibration data and default to the original Control when confidence/validation skill is insufficient.

The Control scientific USD 5.89M remains the principal model benchmark and v10.8.44 USD 1.078M remains the best constrained historical research path so far.
