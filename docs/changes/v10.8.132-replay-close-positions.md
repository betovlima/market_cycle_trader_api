# API v10.8.132 — posição efetiva no fechamento

Em `GET /api/analytics/backtests/{job_id}`, cada linha de `equity` recebe `selected_asset`, recuperado do campo de mesmo nome já persistido nos documentos da série de previsões PORTFOLIO. A consulta é estritamente somente leitura: `timestamp`, `simulation_equity`, `reference_equity`, `drawdown`, `selected_asset`.

O motor registra decisões baseadas no fechamento de t, com execução prevista na abertura de t+1. Por isso **não** identificamos CASH em t a partir de uma decisão de t; o frontend usa o `selected_asset` efetivamente registrado em cada sessão. Em registros antigos que não possuam `selected_asset`, a resposta inclui `null` e não reconstrói posição por eventos, retornos ou outros dados. `equity_history.csv` exporta o mesmo campo, inclusive dentro do pacote ZIP do replay.

Teste de regressão: `tests/test_replay_close_positions_v108132.py`. Não há mudanças no motor de backtest, nas ordens ou na execução operacional.
