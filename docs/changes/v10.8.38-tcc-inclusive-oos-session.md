# API v10.8.38 — include the last requested daily session in TCC OOS replay

## Additional root cause found during v10.8.37 integration

The MCT queue locks a session date, e.g. `analysis_end_date=2026-09-28`. The unmodified TCC v1.0.6 engine uses `pd.Timestamp(analysis_end_date)` and `common_dates.searchsorted(requested_end, side="right")` to determine the last OOS execution row. A date-only `2026-09-28` means `2026-09-28T00:00:00Z`, but an Alpaca daily candle during EDT is stamped at `2026-09-28T04:00:00Z`. As a result, simply copying the MCT date to the TCC config would STILL exclude the target day's daily bar. The old frozen scientific `analysis_end_date=2026-09-17` similarly explains why its last realized OOS execution is 2026-09-16. This is timestamp boundary semantics rather than a data-fetch failure.

## Focused correction

Only for normal `mct_current` reference jobs, the MCT wrapper translates the requested inclusive session date into `23:59:59.999999999 UTC` of the same day before giving it to the unmodified vendored TCC engine. The effective reported `analysis_end_date` stays the original YYYY-MM-DD cutoff; a separate `reference_execution_end_boundary_utc` records the internal inclusive timestamp. The result's `last_oos_execution_date` must equal the job's requested session or the job fails, never silently showing a stale successful capital result.

Explicit `tcc_frozen_main` stays pinned to the exact original scientific `2026-09-17` string, its historical replay outcome is unchanged, and the vendored TCC v1.0.6 source files remain byte-identical. This is a wrapper-only timestamp conversion, not a new strategy, heuristic, margin calibration or modified market prices.

## Regression

`test_unmodified_tcc_execution_includes_last_alpaca_daily_bar` invokes the **actual unmodified TCC** `_analysis_decision_dates` with session-start 04:00 UTC candles. It confirms that date-only 28 September incorrectly excludes 28 September and that the wrapped inclusive UTC boundary includes it. Current and frozen source semantics and the fail-closed result guard remain covered in `test_tcc_v106_tuning_selection_and_cutoff.py`; the full existing regression suite runs in CI.
