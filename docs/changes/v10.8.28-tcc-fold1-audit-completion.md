## Root cause of audit failure

The reference CSV loader infers integer dtype for `volume` when all source
values are integral. Verbatim TCC `split_normalize` scales pre-split volume
by non-integer ratios. Pandas rejects writing those fractional values back to
an int64 Series (example: PXLW ratio 3/2). This is an audit adapter problem,
not a structural issue with these assets and not a reason to exclude them.

## Fix

- Upcast audit-local input OHLCV columns to float64 immediately before calling
  the frozen split normalizer. Archived RAW hash validation happens **before**
  this conversion.
- Compare numerical Corporate Action rate fields using Decimal canonical
  values, preserving CUSIP and other identity fields exactly as strings.
- Report partial/incomplete status and full asset count explicitly.
- Truncate verbose Pandas exception strings in the report.
- Add regression tests for non-integral split-adjusted volume, rate formatting,
  and import-time environment configuration.

Changes are limited to MCT audit code and tests. The vendored TCC v1.0.6
engine, the TCC repository, the Strategy profiles and all input snapshots
remain untouched. No Alpaca refresh or new backtest is required.
