# API v10.8.17 — RAW total-causal research data parity

## Problem identified

A Simulation Backtest exported from API 10.8.16 showed that the engine and tuning
changes were active, but the market-data layer was still using the legacy MCT
research protocol.

Observed in the exported experiment manifest:

- `alpaca_adjustment = all`;
- `mongo_cache_enabled = true`;
- `research_market_data_mode = backtest_bootstrap_missing`;
- 56 configured and executed assets, including `DOC`;
- every symbol resolved from an Alpaca/Mongo identity with
  `adjustment = all`.

This differs materially from the validated TCC protocol:

- Alpaca SIP 1Day RAW bars;
- causal split normalization performed locally;
- Corporate Actions collected independently;
- structural identity changes excluded reproducibly;
- `DOC` excluded because it is the acquiree in a merger to `PEAK`;
- 55 eligible assets for the frozen 2026-09-17 research window.

The 10.8.16 Simulation therefore validated the new backtest engine against the
wrong logical dataset for TCC parity.

## Branch and version

- API: `10.8.17`
- branch: `feature/v10.8.17-raw-research-data-parity`
- parent: `feature/v10.8.16-botorch-tuning-parity`

## Research-only data protocol

A new execution-level field is introduced:

```text
research_market_data_protocol = raw_total_causal_v1
```

It is the default for new Backtest Execution requests.

The legacy profile field `alpaca_adjustment` is intentionally not removed.
Operational Paper/Live behavior continues to use the Strategy configuration.

For research Simulation, the effective configuration is derived without mutating
the Strategy profile:

```text
profile alpaca_adjustment = all
        ↓
research effective config
        ↓
alpaca_adjustment = raw
research_market_data_protocol = raw_total_causal_v1
```

The effective configuration is persisted in `backtest_comparisons` and is
included explicitly in exported artifacts.

## RAW Mongo identity

Research RAW bars use the existing MongoDB bar cache with a different identity:

```text
symbol
interval = 1Day
feed = sip
adjustment = raw
timestamp
```

Therefore legacy `adjustment=all` documents cannot be silently reused.

When `research_market_data_mode = backtest_bootstrap_missing`:

1. if the RAW identity is absent, Simulation downloads RAW Alpaca bars;
2. if RAW exists but ends before the locked research cutoff, Simulation refreshes
   it through the cutoff using the configured Mongo overlap;
3. the resulting RAW bars are persisted in MongoDB;
4. Model Tuning never performs this download.

The existing `adjustment=all` cache remains untouched.

## Corporate Actions cache

A new MongoDB collection is used:

```text
alpaca_corporate_actions
```

Each symbol stores the Alpaca Corporate Actions query range and normalized
action payload needed by the research protocol.

Simulation may bootstrap/refresh this cache from Alpaca.

Model Tuning is database-only. If the required Corporate Actions are not already
available, tuning fails instead of reaching the internet.

## Causal split normalization

The split rule is copied from the validated TCC implementation.

For each forward/reverse split, historical sessions strictly before the ex-date
are transformed with:

```text
price_factor  = old_rate / new_rate
volume_factor = new_rate / old_rate
```

Applied to historical:

- open;
- high;
- low;
- close;
- vwap when present;
- volume with the inverse factor.

Trade count is not modified.

The model therefore consumes a continuous split-normalized series while the
underlying Mongo bar source remains RAW.

## Structural identity exclusion

Stock merger, stock-and-cash merger and cash merger events are inspected.

An asset is excluded when:

```text
acquiree_symbol == configured ticker
and
acquirer_symbol != configured ticker
```

No manual bridge, reconstruction or ticker stitching is performed.

This reproduces the TCC rule and explicitly excludes `DOC` when the relevant
DOC → PEAK structural event is present.

The exclusion is written into result metrics and the experiment manifest.

## Effective universe

After structural exclusions, the Simulation constructs a new effective request
containing only successfully eligible assets.

The following are filtered consistently:

- `assets`;
- `calendar_anchor_assets`;
- `research_reference_assets`;
- `research_candidate_assets`.

The new data-driven calendar logic from API 10.8.15 then selects the calendar
source from the eligible prepared frames.

## Model Tuning inheritance

Model Tuning previously reconstructed its frozen execution context from
`job.request`, which contains the original Strategy-profile configuration.

Starting with 10.8.17, it first uses the certified Simulation
`comparison.effective_config`.

This is essential because the effective research config contains:

- RAW adjustment;
- the RAW total-causal protocol;
- structural exclusions;
- the actual eligible universe.

The frozen tuning snapshot is created by loading the same processed
`load_research_market_bars` frames used by Simulation.

Candidates subsequently read that frozen processed snapshot and do not reapply
splits or call Alpaca.

## Reproducibility additions

Per-asset market-data manifests now include:

- `research_market_data_protocol`;
- `source_adjustment`;
- `effective_adjustment`;
- `corporate_action_source`;
- `corporate_action_count`;
- `splits_applied`;
- `structural_identity_verified`.

These fields also participate in the stable research market-data signature where
appropriate.

Top-level result metrics additionally expose:

- `configured_asset_count`;
- `eligible_asset_count`;
- `eligible_total_rows`;
- `total_splits_applied`;
- `total_corporate_actions`;
- `structural_exclusion_count`;
- `structural_exclusions`;
- `research_market_data_protocol`;
- `research_source_adjustment`.

## Export behavior

`strategy_manifest.json` keeps the original Strategy profile configuration and
now also includes the Simulation `effective_configuration`.

`experiment_manifest.json` uses the effective research configuration and
exposes the RAW protocol and structural-exclusion diagnostics explicitly.

This makes the operational Strategy profile and the research-effective dataset
distinguishable instead of silently conflating them.

## Expected parity check for the frozen TCC cutoff

For the frozen 2026-09-17 window and the same 56 configured tickers, the next
Simulation is expected to resolve the validated TCC logical dataset:

```text
configured_asset_count = 56
eligible_asset_count   = 55
eligible_total_rows    = 148060
total_splits_applied   = 17
DOC                    = structural exclusion
research_source_adjustment = raw
research_market_data_protocol = raw_total_causal_v1
```

The MCT market-data SHA-256 is not expected to equal the TCC CSV snapshot hash
because the two projects use different serialization/signature algorithms. The
logical rows, eligibility and split diagnostics are the parity criteria.
