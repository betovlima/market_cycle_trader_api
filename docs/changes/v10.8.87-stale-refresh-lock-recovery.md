# MCT API v10.8.87 - stale live-market refresh lock recovery

## Context

Production confirmed Strategy #29 is already live-runtime compatible:

- trader_compatibility.eligible = true
- code = tcc_u67_live_runtime_ready

The Promote to WINNER button remained disabled because the global control document
still had a stale market-data synchronization lock:

- live_market_refresh_in_progress = true
- live_market_refresh_started_at = 2026-09-28T23:21:42.578Z
- live_market_refresh_source = premarket_plan_refresh
- winner_promotion_guard.code = daily_calibration_data_sync

The lock was many days old and did not represent a current synchronization.

## Change

Adds:

POST /api/research/tcc-u67/recover-stale-live-market-lock

The endpoint clears only an orphaned live-market refresh lock and only after
safety checks.

It releases the lock only when:

1. the lock is older than six hours;
2. no Paper run is in preparing/calibration phase;
3. no Paper run is executing orders;
4. no trade plan has status executing.

It does not:

- submit any Alpaca order;
- change the current Winner;
- reset Paper State;
- modify the current XSD position;
- alter any U67 model or backtest parameter.

## Expected production flow

1. Deploy API v10.8.87.
2. Call POST /api/research/tcc-u67/recover-stale-live-market-lock.
3. Confirm response code stale_lock_released.
4. Call GET /api/admin/strategies/control.
5. Confirm live_market_refresh_in_progress=false and
   winner_promotion_guard.available=true.
6. Refresh the frontend. Promote to WINNER should become enabled.
