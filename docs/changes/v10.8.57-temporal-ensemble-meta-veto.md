# MCT API v10.8.57 — Temporal Ensemble Meta-Veto

## Objective

Try to increase final capital relative to the frozen v10.8.53 reference by
reducing temporal drift. The v10.8.53 Logistic contract is preserved, but
prior source folds are modeled separately instead of pooled into one model.

## Frozen references

The same job must reproduce first:

- v10.8.44 Liquidity-Aware: `US$ 1,078,635.4115518222`
- v10.8.53 One-shot Meta-Veto: `US$ 1,891,417.6670329159`

Absolute tolerance: `1e-6`.

## Component model

Each prior source fold gets its own:

- balanced L2 Logistic Regression;
- C = 0.25;
- same 9 v10.8.53 features;
- chronological 70/30 split within that source fold;
- minimum 20 calibration rows;
- BA >= 0.52;
- ROC AUC >= 0.52.

A component that fails its own gate is excluded.

## Aggregation

For the current test fold:

`P_ensemble = mean(P_component)`

Veto remains:

`P_ensemble <= 0.35`

No new threshold or weight is introduced.

## Fold behavior

- Fold 1: no model.
- Fold 2: only Fold 1 component. This must be exactly equivalent to v10.8.53.
- Fold 3: separate Fold 1 and Fold 2 components, using only fully matured
  labels with `rollout_end_date < test_start`.

The experiment aborts unless the candidate equity curve is identical to
v10.8.53 for all sessions before Fold 3.

## Execution

Unchanged:

- Liquidity-Aware;
- one-shot HOLD;
- next policy call forced to Control;
- costs/fees/execution model;
- frozen snapshot.

## Interpretation

This is post-discovery/exploratory. Improvement in the same historical window
does not constitute future independent validation.

## Endpoint

No new endpoint.

POST:

`/api/admin/control-shadow/reduced-meta-veto/jobs`

The job response exposes:

- `api_version = 10.8.57`
- `research_runner = temporal-ensemble-meta-veto-v1057`

## Decision rule

The candidate is an advance only if its final capital exceeds the exact
v10.8.53 reference under the same replay.
