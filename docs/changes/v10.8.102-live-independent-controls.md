# API v10.8.102 — Live independent monitoring controls

**Branch**: `feature/live-paper-isolated-workspaces-v1` (same open PR #51); **base**: main API v10.8.100. No merge or deployment executed.

## Cause
Live v10.8.101 was delivered read-only with a `GET /api/live-market/robot/status` that always returned `control_mode=stopped` and `execution_enabled=false`. The corresponding Front v10.7.25 drew Start, Pause, Exit only and Stop but always disabled them.

## Modification
- New isolated MongoDB collections `live_trader_control` (`_id=default`, `revision`) and `live_trader_control_history` with admin user/time/reason. No Paper collection touched.
- New admin-only `POST /api/live-market/robot/mode` with `mode`, optimistic `expected_revision`, reason and mandatory literal `confirm=LIVE_MONITORING_ONLY`.
- Accepted Live modes: `active`, `paused`, `exit_only`, `stopped`. State read from separate MongoDB collection by `GET /api/live-market/robot/status`.
- Require separate Alpaca Live credentials for `active` and `exit_only`; no fallback to Paper credentials.
- **These modes affect read-only monitoring policy only.** There is no real-order executor or scheduled Live trading. `execution_enabled=false`, `scheduler_alive=false` and `order_submission_enabled=false` remain invariants of every mode.
- `exit_only` records a future policy, **does not currently sell** assets. In particular, `active` must not be presented as actual Live trading.
- Front v10.7.26 wires buttons to the new endpoint; Live automatic *Portfolio page* polling works only in `active/exit_only`, stops in `paused/stopped`, and manual refresh remains available.
- API and frontend versions increased, test expectation updated, and tests verify four modes, Mongo separation and concurrency conflict.

## Validation
- `tests/test_live_control_modes.py`, `tests/test_live_paper_isolation.py`, existing CI parity tests.
- Independent frontend build checks buttons and memoized polling; no live broker orders tested or placed.
- Status and confirmation must visibly disclose monitoring-only scope.

## Future
Real Live trading requires separately reviewed and explicitly authorized executor, risk limits, circuit breaker, calendar, idempotent order recording and broker reconciliation. Frozen Winner #30, Paper scheduler and CAPR Paper position remain unaffected.
