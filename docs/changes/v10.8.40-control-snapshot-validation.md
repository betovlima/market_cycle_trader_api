# API v10.8.40 — Control snapshot validation (no redownload and no trading)

## Cause and decision
API v10.8.39 completed the first Control Shadow job with a new Alpaca RAW/SIP
snapshot through XNYS 2026-09-28 (56 requested, 55 eligible, DOC excluded).
The decision CASH -> AVGO is a prospective, hypothetical action only.
Its `calibration_score=-0.6868088598099447` is a sum of risk-adjusted
rewards, **not** a -68.68% account return. The first job did not report
all candidate scores, calibration equity and drawdown, or the full expanding
walk-forward OOS portfolio. Repeating the Alpaca download is unnecessary.

## Implementation
- A new **admin-only** POST
  `/api/admin/control-shadow/validation/jobs` accepts an existing
  `source_job_id` and a literal confirmation. It verifies that the Mongo
  source job completed with `fresh_alpaca_raw_sip_local_mct_snapshot`,
  matched date and stored snapshot SHA. No path is accepted from HTTP.
- Loader reopens ONLY `dados/control_shadow/snapshots/<source_job_id>`,
  verifies recorded source contract, manifest hash and every RAW/normalized/
  corporate-actions file SHA-256, expected universe and structural exclusions.
  A missing/altered file fails closed. No broker call and no download.
- Calibration trains the source Control LightGBM on the same causal
  training window and computes the four candidate scores (0, 0.0025,
  0.005, 0.01), calibration equity, drawdown and chronological actions.
  It also compares the original v10.8.39 margin and score and records
  `original_shadow.reproduced`; discrepancies are surfaced, not masked.
- Full OOS execution reuses `tcc_v106_reference.research_challengers`
  scientific LightGBM engine and the original fee/slippage helpers. It
  uses expanding walk-forward folds, purge, model calibration in each fold,
  next-open simulated fills, and an inclusive XNYS cutoff adapter. It exports
  equity vs equal-weight buy-and-hold, decisions, trades, folds, Sharpe,
  CAGR, capital and maximum drawdown. This OOS replay is distinct from the
  one-date v10.8.39 shadow decision and its last fitted model.
- Dedicated Mongo collection `control_shadow_validation_jobs` stores
  progress and results; a unique active key prevents concurrent validation
  jobs. Logs also appear on the PyCharm/Uvicorn console.
- Generated outputs are isolated by validation ID under
  `dados/control_shadow/snapshots/<source_job_id>/validation/v10.8.40/<validation_job_id>/`.
  The source snapshot CSVs and manifest are **never overwritten**.
  Outputs: `summary.json`, `calibration_curves.csv`,
  `calibration_decisions.csv`, `oos_capital_curve.csv`,
  `oos_decisions.csv`, `oos_trades.csv`, and three PNGs:
  `calibration_capital.png`, `oos_capital.png`, `oos_drawdown.png`.
- Failures become `status=failed` with stack trace in the local console
  and sanitized error in the job. Failures do not authorize orders.

## How to run in Git Bash (API repository root)
```bash
git fetch origin
git switch feature/v10.8.40-control-snapshot-validation
git pull --ff-only origin feature/v10.8.40-control-snapshot-validation

PYTHONPATH=src python -m unittest discover -s tests -p "test_control_snapshot_validation.py" -v
PYTHONPATH=src python -m unittest discover -s tests -p "test_*.py" -v
```

Keep `MCT_CONTROL_SHADOW_API_ENABLED=true` in the **local** API `.env`.
Restart the **local** PyCharm API process (one worker, no hot reload during
heavy jobs) and open `http://127.0.0.1:8000/docs`. Under
**Control Shadow — no orders**, execute:

POST `/api/admin/control-shadow/validation/jobs`
```json
{
  "confirm": "VALIDATE_EXISTING_CONTROL_SNAPSHOT_NO_ORDERS",
  "source_job_id": "control-shadow-9602cef2679f4d2a"
}
```
Expected HTTP 202 response: a *new* `control-validation-...` job ID.
Follow GET `/api/admin/control-shadow/validation/jobs/{job_id}/logs`
or the PyCharm console. When completed, GET
`/api/admin/control-shadow/validation/jobs/{job_id}` returns margin scores,
source reproduction status, OOS metrics, fold summaries and local report path.

## Safety and interpretation
- The calibration objective is risk-adjusted reward; negative score is not
  directly a percentage return. Calibration is used to choose the margin,
  and must not be relabeled independent OOS evidence.
- A historical scientific OOS backtest is simulated performance, not proof
  of production/live execution parity. Current Alpaca series can differ from
  the original TCC frozen historical series; do not conflate capital amounts.
- This code contains no order, Paper executor, Winner promotion, strategy
  catalog change, frontend change or TCC mutation. Research-only #28 remains
  ineligible for Trader promotion. Winner and real portfolio unchanged.
- The thread-based job needs one local worker; restart interrupts an active
  validation. Do not merge/deploy until full branch CI and local snapshot
  smoke test have been checked.
