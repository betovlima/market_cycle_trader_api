# API v10.8.23 — Alpaca current-data audit

## Context

Market Cycle Trader (MCT) and the standalone TCC have different data contracts.

- **MCT is operational**: each new Simulation campaign must consume the current historical series delivered by Alpaca. If Alpaca revises historical bars, MCT must use the revised series.
- **TCC is scientific/reproducible**: its research snapshot remains frozen and versioned. Later Alpaca revisions must not mutate the TCC experiment.

Therefore numerical equality between MCT and the frozen TCC snapshot is not a release gate. The required parity is methodological (features, targets, folds, model policy, causal split normalization and simulation rules), while the market-data inputs may legitimately differ.

## Problem

Before this version a full RAW research refresh replaced the cached Alpaca series, but the previous series was not compared with the newly downloaded one before replacement.

As a result, a later change in capital could not be cleanly attributed to one of two causes:

1. Alpaca revised historical OHLCV; or
2. the MCT methodology/code changed.

This is especially important because Alpaca can revise historical data over time and MCT intentionally follows the current provider state.

## Change

During a full RAW research refresh, MCT now:

1. reads the currently cached RAW series for the locked window;
2. downloads the current RAW/SIP series from Alpaca;
3. compares the old and new OHLCV **before replacing MongoDB data**;
4. records deterministic SHA-256 fingerprints and row-level drift statistics;
5. only then replaces the cached series with the newly downloaded Alpaca series;
6. continues the existing causal corporate-action normalization and Simulation;
7. freezes the processed Simulation snapshot for Model Tuning as before.

The comparison is exact for the model-input columns:

- open
- high
- low
- close
- volume

Separate audit hashes also include `vwap` and `trade_count` when available.

## New per-asset audit fields

The reproducibility manifest now exposes:

- `downloaded_at`
- `raw_sha256`
- `raw_audit_sha256`
- `previous_raw_sha256`
- `previous_raw_audit_sha256`
- `history_comparison_available`
- `historical_data_changed`
- `changed_rows`
- `added_rows`
- `removed_rows`
- `first_changed_timestamp`
- `last_changed_timestamp`
- `normalized_sha256`
- `history_audit_source=alpaca_raw_pre_replace`

`normalized_sha256` is the existing model-data fingerprint after causal split normalization. The research signature remains content-based; download timestamps and prior-history metadata do not alter the model-data signature.

## Aggregate diagnostics

Simulation metrics/summary now include:

- `market_data_history_compared_asset_count`
- `market_data_history_changed_asset_count`
- `market_data_history_changed_assets`
- `market_data_history_comparison_unavailable_assets`

The worker log emits one `MARKET_DATA_DRIFT` line per asset when audit metadata is present.

## Data lifecycle

### Simulation

A new RAW research Simulation continues to refresh from current Alpaca history. It does **not** reuse the frozen TCC files.

### Model Tuning

Model Tuning continues to use the certified frozen Simulation market-data snapshot and remains database-only. No Alpaca download is introduced into tuning.

### TCC

No TCC data file is changed by this release. The TCC frozen research snapshot remains immutable and versioned independently.

## Compatibility

This release does not introduce a new strategy mode and does not change portfolio policy, model hyperparameters, feature engineering, target construction, walk-forward scheduling or trade execution rules.

It adds auditability around the already-required current-Alpaca refresh.

## Expected validation on the next Simulation

For each eligible asset, verify:

1. `raw_sha256` is present;
2. `previous_raw_sha256` is present when an older cached RAW series exists;
3. `historical_data_changed=false` when Alpaca returns identical OHLCV;
4. drift counts and timestamps are populated when Alpaca has revised history;
5. the newly downloaded current Alpaca series is the one used by the Simulation;
6. the resulting certified tuning snapshot uses exactly that Simulation data;
7. Model Tuning performs no Alpaca requests.

## Next steps

After a successful Simulation, archive/export the experiment manifest and compare the new drift diagnostics against the previous run. A capital difference should then be interpreted together with the Alpaca history-drift evidence instead of being compared directly with the frozen TCC capital.
