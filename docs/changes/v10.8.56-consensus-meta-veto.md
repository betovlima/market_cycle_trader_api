# MCT API v10.8.56 — Consensus Meta-Veto

## Objective

Try to increase final capital relative to the frozen v10.8.53 reference by
reducing false-positive vetoes without allowing the v10.8.55 regressor to
replace the primary classifier.

## Frozen references

The same job must reproduce first:

- v10.8.44 Liquidity-Aware: `US$ 1,078,635.4115518222`
- v10.8.53 One-shot Meta-Veto: `US$ 1,891,417.6670329159`

Absolute tolerance: `1e-6`.

## Primary model

Exact v10.8.53 classifier:

- balanced L2 Logistic Regression;
- C = 0.25;
- same 9 features;
- classifier fold gate unchanged;
- candidate veto when `P(ROTATE better) <= 0.35`.

## Secondary model

Exact v10.8.55 expected-advantage regressor:

- Ridge Regression;
- alpha = 1.0;
- same 9 features;
- sign Balanced Accuracy >= 0.52;
- Spearman(predicted delta, actual delta) > 0.

## Consensus rule

The consensus cannot create a new veto.

1. If the classifier does not request a veto, execute Control.
2. If the classifier requests a veto and the regressor is enabled:
   - veto only when `predicted_delta_capital_fraction <= 0.0`;
   - otherwise cancel the classifier veto and execute Control.
3. If the classifier requests a veto and the regressor is disabled:
   - preserve the exact v10.8.53 classifier veto.

This makes v10.8.53 the default/fallback policy.

## Temporal protocol

Unchanged:

- Fold 1: no model;
- Fold 2: fully matured Fold 1 labels only;
- Fold 3: fully matured Fold 1+2 labels only;
- `rollout_end_date < test_start`;
- one-shot HOLD;
- next policy call forced back to Control.

## Interpretation

This experiment is exploratory/post-discovery because the consensus idea was
chosen after inspecting the rejected v10.8.55 result. Even if capital improves,
future independent validation is still required.
