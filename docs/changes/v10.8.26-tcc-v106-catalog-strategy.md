# API v10.8.26 — TCC v1.0.6 as a normal Research Strategy

## Objective

Make the frozen TCC v1.0.6 reference engine behave like a normal Strategy in
the MCT Strategy Catalog.

The previous v10.8.25 reference API proved that the exact TCC engine could be
vendored inside MCT, but it required a parallel endpoint to start the run.

v10.8.26 removes that operational inconvenience.

## New workflow

Call once:

`POST /api/research/tcc-v106/strategy`

The endpoint:

1. creates the next Strategy Catalog entry from the current Research Strategy;
2. mirrors the frozen TCC v1.0.6 Control parameters into the Strategy document;
3. stores the frozen LightGBM model parameters from TCC v1.0.6;
4. binds the Strategy to the vendored TCC v1.0.6 backtest engine;
5. selects only that Strategy for Research/Backtest;
6. leaves the Model Tuning selection unchanged.

With the current catalog ending at Strategy #11, the first installation is
expected to create Strategy #12. The sequence is not hard-coded; the catalog
remains the source of truth.

Calling the installer again is idempotent for the same frozen source commit. It
reuses the existing reference Strategy rather than creating another Strategy.

## Normal Simulation

After installation/selection, the user starts Simulation normally:

`POST /api/jobs`

The normal job queue reads the selected Strategy's engine binding and routes the
job automatically to:

`market_cycle_trader_api.engine.tcc_v106_reference_backtest`

No special run endpoint is required.

The standard MCT job APIs remain valid:

- `GET /api/jobs/{job_id}`
- `GET /api/jobs/{job_id}/results`
- `GET /api/jobs/{job_id}/export.zip`

The normal Backtest Simulation UI can therefore track progress and results using
the same job contract it already uses.

## Strategy contract

The catalog Strategy mirrors the frozen TCC v1.0.6 Control contract, including:

- 56 requested assets;
- start date 2016-01-01;
- scientific cutoff 2026-09-17;
- CPU;
- nondeterministic execution;
- LightGBM n_jobs=-1;
- horizons 5/10/20/40/60;
- weights 0.10/0.15/0.20/0.30/0.25;
- minimum training rows 700;
- calibration 126;
- test 504;
- purge 60;
- switch margin 0.0005;
- switch-margin candidates 0/0.0025/0.005/0.01;
- minimum holding 2;
- minimum utility edge 0.001;
- downside penalty 0.20;
- drawdown penalty 0.35;
- initial capital USD 10,000;
- fractional shares;
- zero slippage and zero commission;
- LightGBM 329 estimators and the frozen v1.0.6 model parameters.

MCT still supplies the current Alpaca research data through the homologated MCT
market-data pipeline. The TCC frozen CSV snapshot is not imported.

## Engine binding

The Strategy document records:

- `backtest_engine_binding = tcc_v106_reference`
- `reference_engine_id = tcc-v1.0.6-verbatim`
- repository, tag and commit provenance.

The normal job queue records the same binding and selects the dedicated engine
module automatically.

## Lifecycle safety

A reference-engine Strategy is Research-only.

It:

- can run through normal Backtest Simulation;
- can have a completed last-backtest record;
- cannot be selected for Model Tuning;
- cannot be promoted to Trader Winner;
- does not change Paper/Live execution;
- does not modify the TCC repository.

This prevents an isolated scientific reference engine from being promoted into a
live runtime that does not implement the same engine.

## Control vs Soft

One normal Simulation of this Strategy executes both frozen TCC variants:

- `tcc_v106_control`
- `tcc_v106_soft`

The job therefore reports two runs and the normal export ZIP contains both.

## Expected experiment

After installing the catalog Strategy:

1. confirm the Strategy Catalog shows the new Strategy as RESEARCH;
2. use the normal Start Simulation action;
3. follow the normal progress card;
4. compare `tcc_v106_control` and `tcc_v106_soft` in the normal results;
5. export the normal job ZIP.

This directly answers whether the exact frozen TCC engine, operating through the
normal MCT Simulation lifecycle and MCT's current Alpaca data, reproduces the
historical TCC capital path.
