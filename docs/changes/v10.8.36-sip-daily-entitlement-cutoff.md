# API v10.8.36 — recent historical SIP daily-query cutoff

## Incident

Production reference Backtest `20260928T205714-b2259a83` failed on the first asset (NVDA) with Alpaca HTTP 403: `subscription does not permit querying recent SIP data`.

The normal TCC v1.0.6 reference simulation selected the last safely completed XNYS session, **2026-09-28**, correctly. However, `_download_alpaca_bars` used the historical single-request API end of next-day midnight UTC, `2026-09-29T00:00:00Z`. That timestamp was still in the future during the run, and Alpaca interpreted it as a recent SIP query. This is an entitlement/window failure, **not** rate limiting, stale Mongo source, or an error in selecting 28 September's cutoff.

Alpaca's historical SIP feed on accounts without real-time SIP requires the explicit `end` to be at least 15 minutes old. The XNYS completed-session guard already applies a 20-minute margin after the actual market close.

## Correction

`engine.market_data.daily_historical_api_end` preserves the original TCC end (`cutoff + 1 UTC day`) when it is already at least 15 minutes old, and for IEX. **Only if a SIP single daily request's original end is too recent or in the future**, the request ends at the *actual XNYS close* for its requested completed session, subject to an independent 20-minute safety check. An early close is resolved through XNYS rather than a hardcoded 16:00 ET.

For 2026-09-28 (normal close 16:00 EDT), after 16:20 EDT: `end=2026-09-28T20:00:00Z`, instead of `2026-09-29T00:00:00Z`. The daily bar is timestamped at the start of the session; the requested cutoff and complete daily bar are unchanged. If the requested session is not safely closed, the downloader **fails explicitly**. No automatic IEX substitution, next-day access, silently older cutoff, adjusted historical prices or frozen CSV fallback is introduced.

Provenance now records `research_bar_end_mode` and `research_bar_api_end_utc` for the historical full request, so the precise provider request can be audited. Historical frozen TCC reproduction keeps its original request end where the entitlement window allows it.

## Scope and invariants

Only the historical daily one-request downloader is changed. The scientific TCC engine and weights, Control/Soft variants, complete RAW/SIP refresh per normal Simulation, corporate action protocol, and TCC-Main frozen scientific snapshot are unchanged. No strategy catalog mutation, Winner promotion, Paper order or change to operational live price source. Winner #27 and current positions are not modified by this code change.

Changing only the API query end from next midnight to completed close may yield identical daily bars, but production success must be checked against Alpaca's real entitlement and the job's actual data completeness. Do not claim exact OOS/capital parity between different requested source snapshots.
