# API v10.8.25 — TCC v1.0.6 reference API

## Objective

Run the exact TCC v1.0.6 engine inside Market Cycle Trader without modifying
the TCC repository and without replacing the current Strategy #11 engine.

The purpose is to isolate code-path differences between:

- current MCT Strategy #11;
- the frozen TCC v1.0.6 Control;
- the frozen TCC v1.0.6 Soft Horizon Consensus.

## Source of truth

The reference engine is copied from:

- repository: `betovlima/tcc_mba_usp_data_science_analytics`
- tag: `v1.0.6`
- commit: `c0d71772092f0c26c9f28f0211b9933e9c396b95`

The eleven files under:

`src/market_cycle_trader_api/tcc_v106_reference/`

are verbatim copies of `tcc_engine/` from that tag.

Regression tests calculate each vendored file's Git blob SHA-1 and compare it
with the source blob SHA from the TCC repository. This prevents accidental
editing of the frozen reference engine.

## What is copied

The complete TCC v1.0.6 engine package is vendored:

- configuration;
- capital rotation;
- LightGBM research challenger;
- execution cost helpers;
- Soft Horizon Consensus;
- selective opportunity helpers;
- allocation/risk helper modules required by the copied engine;
- rotation diagnostics.

The copied source files are not adapted to MCT conventions.

## What is not copied

The TCC frozen CSV snapshot is intentionally not imported into MCT.

The new API uses MCT's current Alpaca research-data transport and then hands the
prepared market frames to the exact TCC v1.0.6 engine.

Therefore the experiment contract is explicitly:

`MCT current Alpaca data + exact TCC v1.0.6 engine`

and not:

`TCC frozen snapshot + TCC v1.0.6 engine`.

This preserves the MCT operational data rule while isolating the strategy code.

## API

Reference metadata:

`GET /api/research/tcc-v106`

Start a reference Simulation:

`POST /api/research/tcc-v106/jobs`

The job is stored in the normal MCT job infrastructure and can be inspected and
exported with the existing job/export endpoints.

The endpoint executes two variants:

1. `tcc_v106_control`
2. `tcc_v106_soft`

Both are generated by the copied TCC engine.

## Safety and isolation

The reference API:

- does not mutate the TCC repository;
- does not modify Strategy #11;
- does not certify or promote any MCT Strategy;
- does not participate in Model Tuning;
- does not change Paper/Live trading;
- uses a dedicated allow-listed engine module;
- runs as an isolated research backtest process.

The currently selected MCT Strategy is used only to establish the MCT market
data execution snapshot. The reference endpoint requires the exact TCC
56-symbol universe and the LightGBM compound-rotation Strategy mode.

## Validation

Automated tests verify:

- every copied TCC engine file is byte-identical at the Git-blob level to the
  corresponding v1.0.6 source file;
- the frozen v1.0.6 configuration remains CPU, nondeterministic, LightGBM,
  switch-margin base 0.0005, candidates 0/0.0025/0.005/0.01, and horizons
  5/10/20/40/60;
- the dedicated engine module is explicitly allow-listed by the job runner.

## Next experiment

Run the reference API while Strategy #11 is selected.

Compare:

- `tcc_v106_control`
- `tcc_v106_soft`
- the normal Strategy #11 v10.8.24 result.

If the copied Control moves from approximately USD 5.54M toward the TCC
reference near USD 10.09M using the same MCT data source, the remaining cause is
inside the engine/code path.

If it stays near the current MCT result, the remaining cause is primarily in
the data snapshot/preprocessing contract rather than the Control/Soft engine
implementation.
