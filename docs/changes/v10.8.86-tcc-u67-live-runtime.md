# MCT API v10.8.86 - TCC U67 protected live runtime

## Objective

Enable the already validated TCC U67 Strategy to be promoted to Trader Winner
without changing its scientific backtest contract and without resetting the
existing Alpaca/Mongo paper position.

The validated Strategy remains:

- mode: `COMPOUND_ROTATION_SWING_TCC_U67_V1210`;
- requested universe: 67 symbols;
- effective backtest/runtime universe: 65 symbols after the same DOC/CLMT
  structural filtering used by the homologated MCT run;
- model: protected LightGBM Utility snapshot;
- scientific source: TCC main commit
  `4b5f16030afa8b850790747bb0e3e3063d233e79`;
- validated MCT capital: US$ 78,782,538.31 at 2026-09-17 and
  US$ 76,927,051.39 at 2026-10-06.

## Problem fixed

API v10.8.85 deliberately installed U67 as backtest-only:

- `backtest_engine_binding=tcc_u67_v1210_operational_backtest`;
- `live_trader_eligible=false`;
- promotion compatibility returned
  `research_reference_engine_not_live`.

This prevented Strategy #29 from becoming Winner even after its production
backtest reproduced the validated U67 result.

## Live runtime

v10.8.86 adds a protected next-open decision path:

`paper_trading -> live_model_signal -> build_live_tcc_u67_decision`

The live decision:

1. receives the current managed position and holding-session count from the
   existing Paper state;
2. downloads a new full Alpaca RAW/SIP daily snapshot through the latest safely
   completed XNYS session;
3. downloads Corporate Actions;
4. applies the same split normalization and structural filtering used by the
   validated U67 backtest;
5. rebuilds the fixed eligible U56 calendar;
6. trains/calibrates the protected U67 LightGBM using only completed history;
7. evaluates the latest completed session prospectively for the next open;
8. applies the same minimum-hold, cash, expected-edge and switch-margin rules.

No future next-open candle is used for the live decision.

## Position preservation

Winner promotion remains metadata-only:

- no Alpaca order is submitted by promotion;
- `broker_interaction_performed=false`;
- `operational_state_preserved=true`;
- `paper_state_reinitialization_required=false`;
- the current managed symbol, quantity, cash and holding sessions are preserved.

Therefore, if production is currently long XSD when Strategy #29 is promoted,
the promotion itself keeps XSD. On the next scheduled evaluation, U67 receives
`current_asset=XSD` and the existing `holding_sessions`. XSD is sold only
if the normal U67 policy later chooses another asset or CASH.

## Safety gates

Promotion is permitted only when all of these match:

- exact U67 strategy mode;
- exact `tcc_u67_v1210_operational_backtest` binding;
- exact protected 67-symbol configuration;
- exact protected LightGBM snapshot;
- no active Winner promotion;
- no Paper order execution;
- no daily calibration/data-refresh critical section.

Any contract drift fails closed.

## Market data audit

Every U67 live preparation creates an immutable snapshot under:

`dados/tcc_u67_operational/snapshots/trader-u67-<session>-<id>/`

The resulting Paper plan records:

- live cutoff;
- U67 snapshot job ID;
- U67 snapshot SHA-256;
- effective assets;
- structural exclusions.
