# API v10.8.134 | Bloqueio seguro de estratégias históricas sem motor executável

## Sintoma e causa
`POST /api/jobs` falhava com status 500 e erro Pydantic `BacktestRequest.strategy_mode` quando o catálogo mantinha em `research_strategy_id` uma estratégia cujo `strategy_mode` não existe mais no `StrategyMode` atual. Exemplo observado: `COMPOUND_ROTATION_SWING_TCC_U75_DAILY_CASH_V101`.

## Correções
- `get_research_strategy_context` verifica a compatibilidade do modo antes de chamar Pydantic, sem alterar o perfil salvo.
- Ambas as seleções para `Strategy Research` agora impedem novas escolhas de modos descontinuados com status HTTP 409.
- `POST /api/jobs` transforma o erro em 409 com código estável `RETIRED_BACKTEST_STRATEGY_MODE`, tanto para a verificação explícita como para falha legada de validação Pydantic.
- Nenhum novo job, treinamento, download Alpaca, ou ordem é iniciado em caso de conflito. O usuário deve selecionar explicitamente uma estratégia executável em **Configurações do Sistema > Estratégias**.
- **Sem conversão silenciosa de U75 para U67/U77**, sem limpeza de documentos, sem alterações ao Winner ou às políticas operacionais e sem remoção de backtests históricos.

## Testes
`python -m unittest tests.test_retired_backtest_mode_guard_v108134 -v`
`python -m unittest discover -s tests -p "test_*.py" -v`

Verificações: rejeição U75, aceitação de um modo conhecido, seleção sem escrita no controle, POST sem criação de job, tratamento de ValidationError legado, 409 nas rotas do catálogo. A reexecução de uma política U75 histórica exige restaurar código/ambiente compatível e validado; não é consequência desta correção.
