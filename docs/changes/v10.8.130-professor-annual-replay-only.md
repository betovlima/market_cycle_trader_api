# API v10.8.130 — Professor with Annual Replay-only access

## Goal
Allow an invited professor to inspect stored historical Backtest Annual Replay while preventing all unrelated MCT API and UI access.

## Changes
- New `replay_guest` invitation role, verified by the existing authorized Google email invitation mechanism. Invitation expiry, revocation, session idle expiry and audit records remain managed by the existing Access service.
- Dedicated `annual_replay.view` capability added to the known MCT roles. `replay_guest` has **no other capabilities**.
- A server-side, fail-closed HTTP guard for authenticated `replay_guest` sessions: GET session and two Backtest analytics endpoints, POST logout, OPTIONS; all other routes return HTTP 403. No unrestricted reviewer or viewer role is repurposed.
- No backtest calculations, model parameters, Alpaca requests, broker actions or persistent financial data change.

## Deployment
Deploy API first, then Front v10.7.44. From Administration create an invitation with **Professor (Annual Replay only)**, his authorized Google email and an appropriate expiration. Send the generated invite privately. A professor must not receive viewer, reviewer or administrator access.

## Tests
`python -m unittest tests.test_replay_guest_access_v108130 -v` or existing CI discovery.

## Security notes
The frontend contains only the Annual Replay screen for this role; the server independently rejects other endpoints. The user may browse all completed Backtests listed in Annual Replay; this is not a single-job access filter. Existing replay provides simulated historical results, not live broker state.
