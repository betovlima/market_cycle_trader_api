# API v10.8.22 — Exact TCC LightGBM thread parity

## Context

API 10.8.21 matched the homologated TCC RAW loader exactly:

- one StockBarsRequest per symbol;
- SIP / 1Day / RAW;
- start at 2016-01-01 UTC;
- end at cutoff + one day UTC;
- limit 10,000;
- no chunking.

The real Simulation confirmed that loader contract but still produced:

- Control = US$ 5,544,605.11;
- Fold 1 calibrated margin = 0.0100;
- Fold 2 = 0.0100;
- Fold 3 = 0.0000.

Therefore the RAW transport difference is eliminated.

## Remaining code difference found

The homologated TCC main passes the model snapshot value directly to LightGBM:

```python
n_jobs=int(settings["n_jobs"])
```

The MCT API still passed it through:

```python
_effective_n_jobs(...)
```

which can silently override the certified snapshot through
`MCT_MODEL_THREADS_OVERRIDE`.

The exported configuration could therefore report `n_jobs=-1` while the
actual LGBMRegressor received another value.

## Change

Research LightGBM now uses the exact frozen snapshot value:

```text
LightGBM n_jobs = settings["n_jobs"]
```

For the current Control:

```text
n_jobs = -1
```

No environment override is applied to research LightGBM fitting.

Operational behavior outside this research fitter is not changed.

## Diagnostics

- `lightgbm_thread_contract = tcc_snapshot_exact`.
