# API v10.8.37 — current reference OOS cutoff and independent Model Tuning selection

## Observations and root causes

Production reference Backtest `20260928T223448-20013712` completed using `input_source=mct_current` and the requested 2026-09-28 cutoff. Yet its Control/Soft execution stopped on 2026-09-16, reproducing the old capital outcome. In `tcc_v106_reference_backtest._tcc_variant_configs`, the MCT wrapper constructed both variants from the scientific TCC v1.0.6 config, whose `analysis_end_date=2026-09-17`; it failed to propagate the job's operational cutoff. The source loader and source date were newer, but the replay still used the historic scientific window.

The user's Model Tuning video shows Strategy #28 (TCC reference) and `No compatible completed baseline execution was found`. The generic tuner only accepts ordinary `lightgbm_utility` portfolio results and an exact matching Strategy ID/configuration hash/model settings hash; TCC reference jobs produce distinct Control/Soft backends and use a different execution engine. Never relabel a reference job as an ordinary baseline: its tuning candidates would use the wrong engine. An additional genuine selection bug: `model_tuning_strategy_id` was overwritten with `research_strategy_id` on every catalog read; both the server tuner and Front also read the Research strategy rather than the dedicated tuning selection. Installing/selecting the research-only #28 consequently broke tuning for unrelated strategies.

## Fix and invariants

1. `_tcc_variant_configs` takes the queued immutable MCT execution request and passes its `analysis_end_date` to Control and Soft **only when source is `mct_current`**. Explicit `tcc_frozen_main` retains 2026-09-17. The vendored scientific TCC v1.0.6 files are unchanged. A fail-closed guard requires each current-source result's final OOS execution date to equal the queued cutoff; recording `effective_analysis_end_date` and `last_oos_execution_date` in result metrics prevents silently calling a stale run completed.
2. Restore independent `model_tuning_strategy_id`: a catalog read never overwrites an existing selection. Ordinary Research selection keeps its pre-existing linked-selection behavior. Reference-engine Research selection changes **only** Research, never the tuning selection or Winner. A dedicated `POST /api/admin/strategies/{id}/select-for-model-tuning` changes **only** the tuning role; both backend tuning target and frontend now read the selected tuning ID.
3. Reject reference-engine strategies clearly for generic tuning, including direct API calls. The reference source is eligible only for Research/Simulation. Do not promote it to Trader or feed its Control/Soft results to ordinary model tuning. Missing tuning selection surfaces an empty baseline and informative catalog reason, allowing the frontend selector to load.
4. A standard LightGBM/eligible Temporal strategy still needs a completed matching baseline: same ID, configuration hash and saved model hash. Old or mismatched executions cannot be reused. To obtain a baseline, select that strategy for Simulation, complete a new normal Backtest, return to Model Tuning and Refresh. Research-only #28 can then be selected again without resetting the independent tuning target.

## Production safeguards

- No mutation of the existing Winner #27, Paper holdings, Alpaca orders or current Research/Model Tuning selections by deploying this code. No direct call to the reference installer or live Mongo writes are part of this integration.
- No changes to strategy modes, LightGBM hyperparameters, frozen scientific TCC source files, raw/sip data protocol, or corporate actions. Model Tuning remains Mongo-only on one frozen market-data snapshot per campaign. Reference Simulation still performs complete updated Alpaca RAW/SIP refresh.
- The deploy does not retrospectively modify old job results. Start a **new** reference Backtest after rollout and verify `effective_analysis_end_date`, `last_oos_execution_date` and new Control/Soft outputs.
- Front v10.7.16 pairs with API v10.8.37 for choosing a dedicated tuning target. The Winner remains separate. Leave `MCT_TCC_V106_INPUT_SOURCE` unset or `mct_current` in Railway.
