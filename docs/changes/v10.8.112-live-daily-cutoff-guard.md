# API v10.8.112 — Live guard for previous completed daily session

**Base:** API v10.8.111 on `main`, commit `4963c55d`.
**Branch:** `fix/v10.8.112-live-safe-daily-cutoff`.
**No new endpoints, training variants, tickers or research.**

## Motivation

In the post-close-only Live workflow, a session for Tuesday can be armed as
soon as Monday's market closes at 16:00 New York. The daily Alpaca candle is
not considered safe until **20 minutes after XNYS regular close** (existing
`SAFE_DAILY_BAR_DELAY_MINUTES=20`). Before that the latest safe XNYS day may
still be the preceding Friday. Training immediately at 16:00 would otherwise
create a technically valid but **stale** next-session trade plan.

## New checks

- Before claiming the attempt, `prepare_live_cash_winner_signal` determines
  the **immediately preceding exchange trading day** of the intended execution
  session using `exchange_calendars XNYS.previous_session`.
- It only trains when `latest_safe_completed_xnys_session` equals that
  expected day. Otherwise it returns `waiting_for_completed_daily_bar` with
  the expected/available days. **No model training, attempt-budget increment
  or real order** occurs; the existing Live scheduler polls again later.
- On download start and before persistence, verifies the same decision cutoff.
- The Live real-order executor independently requires `decision_date` equal
  to the immediately preceding XNYS session. A persisted plan with an older
  decision cannot bypass this check.
- Friday → Monday and holiday/weekend transitions use exchange sessions,
  not calendar-day subtraction.

## User flow

The frontend may provide a single opt-in action combining the existing
`GET /api/live-market/robot/status`, `GET /api/admin/system-settings`,
`GET /api/live-market/execution/readiness`,
`POST /api/live-market/robot/mode`,
`GET /api/live-market/portfolio`, and
`POST /api/live-execution/winner/execute` (only when an executable current
session is already frozen). With no current signal, activating Live arms the
**existing** after-close scheduler. It does not permit on-demand new training
while the market is open or immediate trades without a valid prior-close plan.

This release adds **no** manual training endpoint; all Live account and
order-ledger safeguards remain in place.
