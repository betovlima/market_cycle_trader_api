# Counterfactual Rotation Advantage v6.0.0

## Goal

Test one isolated hypothesis:

> Does the persistent ROTATE-versus-HOLD model generalize better when it is trained only on incumbent/challenger states visited by one feasible calibration trajectory, instead of on every asset that was ever Top-1 earlier in the calibration window?

This research branch does not change the opportunity model, universe, costs, walk-forward folds, target horizon, CASH behavior, or live decision threshold.

## Why v6 exists

CRA v4 improved the one-session target by using the shortest frozen Strategy target horizon, but its training dataset still used an expanding set of every historically reachable Top-1 asset as a possible incumbent on every later date.

That creates many counterfactual states such as:

- an asset that was Top-1 weeks ago,
- treated as if the live policy were still holding it today,
- even when no feasible policy trajectory would actually visit that state.

CRA v5 tried to add more temporal memory. The experiment reduced generalization instead of improving it because old calibration regimes contaminated later folds.

v6 returns to the v4 temporal structure and changes only state support.

## Frozen components

- Same 56-asset frozen baseline universe for the first test.
- Same LightGBM Opportunity model.
- Same LightGBM hyperparameters.
- Same walk-forward folds.
- Same costs and exact execution simulator.
- Same persistent relative target horizon: `min(rotation_target_horizons)`.
- CASH remains excluded after the initial entry.
- No new switch margin.
- No new CASH threshold.
- No minimum holding rule.
- Live decisions are still evaluated every session.

## Training design

### Bootstrap stage

A v4-equivalent broad-support model is fitted on the calibration window. This seed model is not used directly in the outer test.

Its only purpose is to generate one feasible calibration policy trajectory.

### Policy-reachable stage

The calibration trajectory starts in CASH and enters the current LightGBM Top-1.

For every later date:

1. Determine the current incumbent from the trajectory.
2. Determine the current LightGBM Top-1 challenger.
3. If both are the same, remain invested and no ROTATE-versus-HOLD sample is needed.
4. If they differ, compute the exact persistent counterfactual advantage:

   `net log return(ROTATE to Top-1) - net log return(HOLD incumbent)`

   over the shortest frozen Strategy target horizon.
5. Store exactly that visited incumbent/challenger state.
6. Use the bootstrap model only to advance the calibration trajectory.

The final v6 model is fitted only on these visited states.

This removes the artificial cross-product of:

`every historical Top-1 incumbent × today's Top-1`

from the final training dataset.

## Live policy

The live policy remains:

- CASH at startup -> enter current Top-1.
- Current asset is Top-1 -> HOLD.
- Otherwise predict persistent rotation advantage.
- Advantage > 0 -> ROTATE.
- Advantage <= 0 -> HOLD.

Zero is the economic indifference point, not a manually tuned threshold.

## Leakage controls

- Calibration opportunity scores are generated by models trained before the calibration block.
- Persistent labels use only the calibration label window.
- The tail equal to the label horizon is purged.
- Outer test sessions are never used to fit the rotation model.
- Test labels are never replayed into later folds.
- v6 does not use v5 expanding temporal memory.

## First run

Run only the frozen 56-asset universe:

```bash
python scripts/research_counterfactual_rotation_advantage_v6.py \
  --strategy-sequence 10 \
  --history-start 2016-01-01 \
  --snapshot-end 2026-09-04 \
  --analysis-start 2020-07-22 \
  --analysis-end 2026-09-03 \
  --series 56 \
  --workers 4
```

The baseline ZIP is resolved automatically from `research_output` when present.


The fit log reports both:

- `seed_samples`
- `policy_reachable_samples`

The gap is intentional. Only the latter are used by the final v6 model.

## Main diagnostics

Per decision:

- `cra6_rotation_advantage`
- `cra6_positive_advantage`
- `cra6_label_horizon_sessions`
- `cra6_training_state_support`
- `cra6_training_decision_dates`
- `cra6_seed_decision_dates`

Per fold:

- final policy-reachable sample count
- seed sample count
- target mean/std
- positive-target fraction
- bootstrap rotation fraction
- in-sample MAE/RMSE

## What would support the hypothesis

The experiment is informative if the final policy-reachable sample count is substantially smaller than the seed sample count and OOS behavior becomes less extreme without sacrificing compound growth.

We care especially about:

- fold-level ending capital,
- ROTATE acceptance when Top-1 changes,
- longest sequences of rejected challengers,
- geometric return per completed position,
- win rate,
- Maximum Drawdown,
- and whether v6 closes the gap to the frozen US$23.52M baseline.

A lower rotation count alone is not a success criterion.

## What v6 does not test

v6 does not test:

- CASH intelligence,
- multi-asset allocation,
- uncertainty thresholds,
- confidence gates,
- minimum holding days,
- a different target horizon,
- expanding temporal replay,
- a different opportunity model,
- or a larger universe.

Those remain separate hypotheses.
